# 曲の分析ソフト（学習用）— 段1・段2

構想は `docs/design/song-analyzer-plan.md`。曲のファイルから「いつ・何が鳴って・何が休むか」と「強弱」のカルテを作り、自分の曲と並べて違いを出す。

## 使い方

```
python3 tools/song-analyzer/analyze.py <曲のファイル> --out <出力フォルダ> [--bpm テンポ] [--name 名前] [--stems]
python3 tools/song-analyzer/compare.py <お手本.karte.json> <自分.karte.json>      # 違いが大きい順に出す
python3 tools/song-analyzer/eval_own.py <カルテ.json> <曲の.json>                # 段1の答え合わせ（自分の曲だけ）
python3 tools/song-analyzer/eval2.py <名前> <曲の.json> [--rerun]                  # 段2の答え合わせ（自分の曲だけ。SA_CACHE と SA_RAW を付けて analyze.py を先に走らせる）
python3 tools/song-analyzer/collect_ia.py <カルテのフォルダ> ジャンル:識別子 …     # お手本集め（ネットレーベルの自由なライセンスの曲だけ。音は分析したら消す）
python3 tools/song-analyzer/summarize.py <カルテのフォルダ> --md <出力.md>        # お手本（ref-）と自分（own）を並べて、幅の外の項目を出す
python3 tools/song-analyzer/restat.py <カルテのフォルダ> <raw のフォルダ>          # 物差しを直したあと、書き起こしから段2の数字を計算し直す
```

- 出力: `<名前>.karte.json`（数字）と `<名前>.karte.png`（図）。`SA_CACHE=<フォルダ>` を付けると、分けた音をためて2回目から速い。
- 入れるもの: `pip install demucs`（MIT。モデル htdemucs_6s を自動で取ってくる）。ほかは librosa・numpy・matplotlib・ffmpeg。
- かかる時間: 3分の曲で1〜2分（CPU 2つ）。

## 分かること（段1）

テンポ・拍・小節の頭／場面の区切りと、似た場面（同じ文字）／小節ごとの音量・低い音と高い音の割合・左右の広がり／歌・ドラム・ベース・和音の楽器が、いつ鳴っていつ休むか／場面の頭で入った楽器・抜けた楽器／重なっている楽器の数／ドラムの手数（キック・スネア・刻み）。

## 当たりやすさ（自分の曲 16「おやつ宣戦布告」v9 で答え合わせ。2026-11-16）

| 項目 | 結果 |
|---|---|
| 歌が鳴っているか（小節ごと） | 99% |
| ドラム | 98% |
| ベース | 100% |
| 和音の楽器（ギター・ピアノ・シンセをまとめて） | 89%（Aメロの短い合いの手を見のがす） |
| ギターとピアノを別々に | **当たらない**（ギター 59%・ピアノは全部見のがし）。分ける道具が、作曲ソフトのギターやピアノを「そのほか」に入れてしまう。だから「和音の楽器」にまとめ、中身は「たぶん」で出す |
| テンポ | 200 の曲を 99.4（半分）と答えた。`--bpm` で直せる。半分のままでも楽器の出入りは 91〜99% 当たる |
| 場面の区切り | テンポを教えたとき 12か所のうち 8か所（±1.5秒）。教えないとき 6か所。余分な区切りも出る |
| キックの手数 | 0.55／拍（正解 0.56） |
| スネア・刻みの手数 | 目安（スネアは多めに数える） |

答え合わせは1曲だけ。本物の録音では、正解が分からないので確かめられていない（本物の録音1曲では、場面が B・C・D・E → B・C・D・E とくり返す形に分かれ、もっともらしい結果だった）。

## 守ること

- 保存するのは作り方の特徴（カルテ）だけ。分けた音は `--stems` を付けたときしか書き出さない。お手本の音そのものはリポジトリに入れない。
- 1曲ぶんのコード進行と旋律は保存しない。短いコード進行（一部）と、旋律の形（長さ・休み・跳び方）は段2で扱う（2026-11-16 人間の指示）。
- お手本にする曲は、権利者本人が自由に使ってよいと出している曲だけ。「CC」と書いてあっても、他人の曲を勝手に上げたものがあるので、1曲ずつ出どころを確かめる。

## 分かること（段2。2026-11-16）

分けた音から書き起こして、**数字と型だけ**をカルテの `stage2` に入れる（`stage2.py`）。

| 何を | 中身 |
|---|---|
| ドラム | キック・スネア・刻みの、1小節16マスの型／型のくり返し（前の小節・2小節前と同じか、8小節に何種類か）／前か2小節前との「似かた」（打つ場所の重なり。聞き取りが1〜2打まちがっても大きく変わらない）／位置ごとの打つ割合／スネアの弱い打／フィルらしい小節 |
| ベース | 1小節の音の数／音を出す場所の型とくり返し／動き方（となりの音・3度・4度5度・オクターブ）／音域／和音の根音を弾いている割合 |
| 和音 | 調（たぶん）／2拍ごとの和音（根音と種類）から、変わる回数・小節の途中で変わる割合・種類の割合・根音の動き方（4度上、2度下…）／**短いコード進行（和音2〜4つのつながりを、度数で、多い順に6つまで）** |
| 歌の旋律の形 | 音の長さ・伸ばし方・句の最後の長さ・食って入る割合・跳ぶ割合・音域・句の上がり下がり・リズムの型のくり返し。**音の高さの並び（旋律そのもの）は入れない** |

### 当たりやすさ（自分の曲 16 v9 で答え合わせ。テンポ 200 を教えたとき）

| 項目 | 結果 |
|---|---|
| キック | 答えのうち当たり 75%・正解のうち見つけた 82% |
| スネア | 79%・68% |
| 刻み（ハイハット） | 54%・53%（**弱い**。ギターやシンバルの高い音とまざる） |
| ベース | 鳴っているか 88%・音の名前 93%・高さまで 86% |
| 歌 | 鳴っているか 93%・音の名前 86% |
| 和音（2拍ごと） | 根音 87%・長短まで 73% |

- 答え合わせは自分の1曲だけ。本物の録音の正解は分からない。本物の歌やドラムは音がゆれるので、**書き起こしのまちがいは本物の録音の方が多いはず**。そのぶん、お手本は「くり返しが少ない」「短い音が多い」方へずれて出る。自分の曲とお手本の「くり返し」の差は、割り引いて読む。
- 速い曲（16分が0.09秒より短い）は、ドラムを8分のマスに寄せる。
- 同じ根音で長と短が入れかわるのは、ほとんど聞き取りのゆれなので、短いコード進行では、その曲で多い方にそろえる。和音の「種類の割合」（7th や sus など）は目安。
- 同じ高さの音をつづけて弾いたかどうか（連打）は、まだ見分けられない。
