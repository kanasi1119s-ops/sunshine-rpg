# ゲームの骨格（全サイクル共通の設計方針）

このファイルは `rpg-cycle` スキルの参考資料です。設計・実装の判断に迷ったらここに戻ってください。

## 2-1. 遊び心地（ドラゴンクエストⅠ〜Ⅵのような王道RPG）
- 見下ろし型2Dのフィールド・町・ダンジョンを歩いて冒険する
- 戦闘は、敵を正面から見る画面（フロントビュー）でのターン制コマンドバトル（たたかう／じゅもん／とくぎ／どうぐ／ぼうぎょ／にげる など。コマンド名は一般的な言葉にする）
- 最大4人パーティ。仲間は物語の進行で加わる・離れる
- レベルアップ、装備の買い替え、宿屋での回復、町の人との会話で情報を集める、という基本の手ざわりを大切にする
- 物語の進行で行動範囲が広がる（徒歩 → 船 → 空の乗り物 など）。広がるたびに「世界が一気に開ける」気持ちよさを演出する
- 中盤以降に**職業（転職）システム**か**仲間モンスター**システムのどちらか1つを入れて、育成の幅を出す（どちらにするかはゲームデザイナーが序盤の設計時に決め、`docs/decisions.md` に記録する）
- 難しさは「ふつうに進めればクリアできるが、雑に進めると全滅する」くらい。全滅したら所持金半分で最後に記録した場所から再開など、やり直しやすくする

## 2-2. ミステリー（空の軌跡のような、章をまたいで深まる謎）
- 物語は**章立て**にする（序章・第1〜8章・終章くらい）。各章は1つの地方と1つの事件を中心に、それ自体で読み終えた満足感があるようにする
- 章ごとの事件の裏に、**物語全体を貫く大きな謎（黒幕・隠された歴史・陰謀など）**を置き、章を進めるごとに少しずつ真相が見えてくるようにする
- 主人公たちは、依頼を受けて問題を解決する組織（例: 町の相談所・調査団などの**オリジナルの組織**）に所属し、**依頼（クエスト）**をこなしながら旅をする
- **推理パート:** 事件の要所で、集めた手がかり（ゲーム内の「手帳」に自動で記録）をもとに、選択式の問いに答えて真相を言い当てる場面を入れる。正解数に応じて評価・報酬が変わるが、**間違えても物語は進める**（進行不能にしない）
- **フェアプレイの原則:** 真相の説明に使う手がかりは、すべて**その説明より前に**プレイヤーが入手できるようにする。後出しの新事実で解決しない
- **町の人の会話は章ごとに変わる。** 事件の前後・章の進行で町の人のセリフを更新し、世界が生きていると感じさせる。何気ない会話にも伏線を混ぜる
- レッドヘリング（わざと疑わしく見せる人物・情報）は使ってよいが、真相が明かされたときに「そういうことだったのか」と納得できるようにする

## 2-3. ボリューム（プレイ時間の予算）
- **メインストーリー: 30〜40時間を目標、最大48時間**（ふつうの人が、サブストーリーをほどほどに寄り道しながら遊んだ場合）
- **サブストーリー（依頼・寄り道の物語）: 合計25本以上**。各章に2〜4本。短いもの（10〜20分）から、複数の章にまたがる長いもの（1〜2時間）まで混ぜる。いくつかは本編の謎の補足や裏ボスにつながる
- **裏ボス:** メインストーリーのクリア後に開放される**クリア後ダンジョン**の最深部に置く。物語上の意味（世界の隠された真実・黒幕のさらに奥など）を持たせる。メインのラスボスより明確に強く、準備と作戦が必要な強さにする
- **プレイ時間の見積もりルール**（バランス担当が `docs/playtime-budget.md` で管理）:
  - 会話文は1分あたり400字で読む想定
  - 移動は、町1つ10〜20分、ダンジョン1つ30〜60分を基準に、地図の広さと敵との遭遇率から見積もる
  - 戦闘は雑魚戦1回30〜45秒、ボス戦5〜10分
  - レベル上げなどの寄り道時間を、メインの1割程度見込む
  - 章ごとに「予定時間」と「見積もり時間」を並べ、合計がメイン48時間を超えそうなら、章の中身を削る・まとめる判断をする

## 2-4. 技術方針
- **ブラウザだけで遊べる**（インストール不要）。PC・スマホ・タブレット（iPad含む）で動く。PCはキーボード、スマホ・タブレットは画面上のボタンで操作
- 言語は TypeScript。描画は Canvas（2D）を基本とし、ゲームエンジン（例: Phaser など）を使うかどうかは Tech Lead が最新の公式情報を確認して決め、理由を `docs/decisions.md` に記録する
- **データとプログラムを分ける:** マップ・会話・イベント・敵・アイテム・呪文・曲は、プログラムから分けたデータファイル（JSONなど）で管理する。シナリオライターや作曲担当がデータを足すだけで中身を増やせる形にする
- **イベントは小さな台本言語で書く:** 会話・選択肢・フラグ・場面転換・戦闘開始などを、データとして書ける仕組みを作る（例: `docs/event-script.md` に書式を定義）
- **セーブ:** ブラウザ内に複数のセーブ枠＋オートセーブ。**セーブデータをファイルに書き出す・読み込む機能**も付ける（ブラウザのデータが消えても続きから遊べるように）。セーブデータにはバージョン番号を持たせ、更新後も古いセーブが読めるようにする
- Viteの `base` は `'./'`（相対パス）。GitHub Pagesでもサイトのサブフォルダでも同じビルドが動くようにする
- 開発用の**デバッグメニュー**（章へのワープ、フラグ操作、レベル変更、無敵、エンカウントなし）を付ける。本番ビルドでは隠す
- **データ容量の予算: 128メガビット（16MiB）以内**（もとは32メガビット。2026-09-30に人間の指示で拡大。録音音源のサウンドフォント約6.6MBを含む）（2026-09-28決定、`docs/decisions.md`参照）。グラフィックはドット絵データ（色番号の配列）、音楽・効果音はWeb Audio APIによる合成のみで作り、画像・音声のバイナリファイルは使わない方針を続ける限り、この予算には余裕を持って収まる見込み。`npm run build` の最後に `scripts/check-build-size.mjs` が `dist/` の合計サイズを自動で確認し、超えていたらビルド自体を失敗させる（CIでも同様）
