# 実行レポートの書き方

`reports/YYYY-MM-DD-HHMM.md`（HHMMは開始時刻・日本時間）として保存する。日付が変わって最初の実行では、あわせて前日分のまとめ `reports/YYYY-MM-DD-summary.md`（前日の日付）を書く。前日のすべての実行レポートを読み、進んだ項目、実行回数、合計作業時間、残った課題をまとめる。

```markdown
# 実行レポート: YYYY-MM-DD HH:MM

## 実行時間
- 開始: HH:MM ／ 終了: HH:MM ／ 所要時間: ○分
- 仕上げた作業項目の数: ○項目（2項目未満の場合はその理由）

## 今すぐ遊ぶ方法
- ローカル起動: npm install → npm run dev（READMEの手順参照）
- GitHub Pages: 公開済み／未公開（公開手順は docs/release-guide.md）
- 今回遊べる範囲: 序章〜第○章（第○章は仮の部分あり）

## 今回の作業
- 担当した工程（roadmap.md の該当項目）
- 完成したこと
- 仮のまま残したこと

## 物語の進み具合
- 章ごとの状態（未着手／設計済み／仮／完成）
- サブストーリー: 完成○本／予定○本
- 伏線台帳: 仕込み済み○件／回収済み○件／未回収で要注意のもの
- 裏ボス: 状態

## プレイ時間の予算
| 章 | 予定時間 | 見積もり時間 | 状態 |
|---|---|---|---|
- メイン合計の見積もり: ○時間（上限48時間）

## BGM・効果音
- 今回作った曲・直した曲
- 曲の一覧の状態（完成○曲／仮○曲／未着手○曲）

## テスト結果
- 毎回の軽いテスト: 合格／不合格（不合格の内容）
- 本格テスト（行った回のみ）:
| ラウンド | 見つけた問題数 | 主な修正内容 | 残った課題 |
|---|---|---|---|
- 自動通しプレイ: 序章〜第○章まで進行不能なし／あり
- ボス戦シミュレーション結果

## 法務チェック結果
- 確認済み項目
- 人間の確認が必要な項目（★重要）

## 人間に相談したいこと
- （外部ソフト・素材が必要な場合の候補と費用、判断が必要な設計、など）

## 次回やること
- roadmap.md の次の項目
```
