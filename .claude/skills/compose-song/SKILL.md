# 曲を作る（Claude Code から作曲ソフトを使う）

APIキーは使わない。曲は、あなた（Claude Code）が「AIソング形式」のJSONで書き、`tools/composer/song.mjs` で確かめて書き出す。

## 手順

1. **形式を読む**: `node tools/composer/song.mjs guide` を実行し、書き方・楽器の一覧・よい曲にするコツを読む。見本は `assets-src/ai-songs/harbor-night.json`。
2. **依頼を整理する**: 場面・雰囲気・テンポ・長さ（指定がなければ60〜90秒）・使いたい楽器。あいまいなら、RPGの場面に合わせて自分で決めてよい。
2.2 **ジャンルの決まりごとを先に学ぶ（2026-10-23 人間の指示。必ず行う）**: 曲を書く前に、そのジャンルの決まりごと（楽器ごとの音域・チューニング、リフや和音の押さえ方、旋律の置き場所、セクションごとの層、ドラム・ベースの型、音作り）を確かめる。
   - まず `docs/sound/` にそのジャンルの手引きがあるか探す（例: 現代のラウドロック・ラウドメタル＝`docs/sound/modern-loud-rock/`、ジャンル全般＝`docs/sound/genre-guides.md`）。あれば読み、設計表に「どの決まりごとを使うか・どれを外すか（理由）」を書く。
   - **無ければ、書く前に調べて学習する**: 実在のバンド・作り手のインタビュー、制作の解説、教本などを複数あたり、数字（音域の音名・Hz・BPM・層の数）で `docs/sound/genres/<ジャンル>.md` にまとめてから作る（出典を書く。曲そのもののメロディ・進行は写さない＝CLAUDE.md 1-1）。
   - 決まりごとはすべて当てはめる必要はない（見本）。ただし、外すときは理由を書く。人間が嫌いと言った音（`docs/sound/banned-sounds.md`）は、決まりごとより優先して外す。
   - 参考の音（`docs/sound/reference-tones.md`）: 人間が渡した参考録音を測った EQ と楽器どうしの大きさの比。ラウドの曲は書き出しで `--ref-tone <id>` を使える（人間が「めっちゃいい」と言ったのは wide-dark-wall）。新しい参考録音をもらったら、同じ手順（音源分離→測る→EQ と大きさの比を計算）で増やす。
   - よくある失敗: 旋律楽器（ギターのリードなど）を、ゲーム音楽のように高い音域でずっと歌わせる。現代のロックでは、旋律は歌の高さ（おおむね G3〜D5）に置き、山場だけ上げる。
2.5. **設計図と進行を先に決める**（曲の個性が決まる所。docs/sound/ai-composition-workflow.md の 2・3 節）: `node tools/composer/chord-pick.mjs --scene <場面> --avoid-last 3` で直近の曲と違う進行の候補を出し、`node tools/composer/song.mjs plan-template` の雛形から `assets-src/ai-songs/<名前>.plan.json`（属性カードとセクション表）を書いて、`node tools/composer/song.mjs plan-check <plan.json>` で直す。description に「入り方: 5。終わり方: …。動機: E4:1 G4:1 A4:2」を書く。コードごとの長さ `Am*2`・セクション別の進行 `sectionChords`・転調 `modulate`・ループの継ぎ目 `loopTail` が使える（`song.mjs guide`）。
3. **曲を書く**: `assets-src/ai-songs/<英小文字の名前>.json` に書く。
   - **完全なオリジナルにする**（CLAUDE.md 1-1）。既存曲のメロディ・特徴的なコード進行を写さない。「〜風」はジャンルと雰囲気だけを参考にする。
   - メロディは曲全体ぶん書き、Aメロ・Bメロ・サビのように変化をつける。ドラムやリフは1〜2小節の型を書けば、くり返して埋まる。
   - 各パートの拍の合計を、コードの数 × barsPerChord × repeats × beats にそろえる（足りない分はくり返し、はみ出た分は切られて注意が出る）。
4. **確かめて書き出す**: `node tools/composer/song.mjs build assets-src/ai-songs/<名前>.json --wav`
   - `×` が出たら、書かれた場所（`parts[0]（メロディ）: 音名が読めません「H4:1」` など）を直して、もう一度 build する。
   - `注意:` は自動チェックのヒント（低音のにごり・同じ音域のぶつかり・単調さ。`--wav` のときは音割れ・低音の多すぎ・強弱の平らさ・途中の無音も）。直すと良くなるので、出たら曲を直して build し直す。直さないなら、理由を報告に書く。
   - 出力は `dist-songs/`（gitには入れない）: 作曲ソフトで開けるプロジェクト（`.sunshine-song.json`）・MIDI・WAV。
   - **段階ビルド**: 一度に全部を書かず、「設計図 → 進行 → 旋律 → ベース・ドラム → 和音 → 飾り」の各段階で `build`（WAVなし）を回し、`×` と `注意:` を読んでから次の段階に進む。注意と `node tools/audio-check/score-check.mjs <曲.json> --facts`（小節番号つきの事実の一覧）を貼って、**1つずつ**直す。
   - 書き出し後: `node tools/composer/song.mjs gate <WAV> --save <曲ID>` で合否表（○／要直し）を出し、直したら同じ測定をもう一度回して `song.mjs log <曲ID> --before .. --change .. --after .. --ear ..` で1行残す。直前の曲との重なりは `song.mjs novelty <曲.json>`。
   - `--edition real|ps2|modern` でサウンドの版を選べる（既定は real＝実楽器）。
   - WAV は Playwright と Chromium が必要。なければ、作曲ソフト（`node tools/composer/build.mjs` で作る `dist-composer/index.html`）でプロジェクトを開き、「WAVで書き出す」を押すよう案内する。
4.5. **点数で仕上げる（人間の指示 2026-10-15）**: 書き出したら、Audiobox Aesthetics の **PQ（制作品質）が 8 点以上になるまで**、別バージョンを作って比べるのをくり返す（下の「点数で仕上げる」）。
5. **聴いてもらう**: WAV（またはプロジェクト）を利用者に渡す。自分では音を聴けないので、「こう作った」（調・テンポ・構成・楽器）を説明し、感想をもらって直す。直すときは同じJSONを書きかえて、もう一度 build する。
6. **ゲームに入れるとき**（頼まれたときだけ）: `--register <曲ID> --scene "<場面>"` をつけて build する。`src/audio/songs/<曲ID>.sunshine-song.json` ができ、ゲームの曲一覧とBGMプレイヤーに入る。鳴らす場面は、ゲーム側の `bgmId` に曲IDを書いて決める。既存の曲を差しかえるときは `docs/decisions.md` に理由を書く（CLAUDE.md 1-7）。

## 注意
- 仮の曲は、`description` と `docs/progress.md` に「仮」と書く（CLAUDE.md 1-4）。
- 言語はすべて日本語（曲名・説明・報告）。

## 点数で仕上げる（PQ 8 点が目標。人間の指示 2026-10-15。はじめ 9 点 → 実在の曲でも出ないので 8 点に変更）

作曲したら、`tools/audio-check/aes-score.py`（Meta の Audiobox Aesthetics。PQ=制作品質・CE=楽しさ・CU=役に立つ度・PC=複雑さ、各1〜10）の **PQ が 8 以上**になるまで調整する。参考: 公開音楽の人気60曲は最高 8.29・平均 6.87・8.5 以上は 0 曲（`docs/sound/listening-toolkit.md`）。
1. 元の曲の点数を測る: `HF_HOME=/tmp/hf python3 tools/audio-check/aes-score.py <WAV>`
2. 試す案を4〜6個まとめて書き（音色・アンプ・歪み量・パートの音量・層の数・ドラムやベースの音源など）、`python3 tools/audio-check/aes-tune.py <曲.json> <案.json> --out <作業フォルダ> --flags "<build のオプション>"` で書き出して比べる（2並列。1案あたり約3分）。
3. いちばん高い案を元にして、次の案を考える。効いた方向は大きく、効かなかった方向はやめる。点数が上がった変更は曲のJSON（と生成スクリプト）に反映する。
4. 8 点に届くか、**3ラウンド続けて 0.1 点も上がらなくなったら**止める。届かなかったら、最高点・試したこと・何が足を引っぱっているかを正直に報告する（8 点に届いたふりはしない）。
守ること:
- **点数より人間の指示が優先。** 禁止の音（`docs/sound/banned-sounds.md`）や、人間が「ドラムを大きく」などと言った方向に逆らって点数を上げない。逆らうと点数が上がる場合は、両方の版を渡して人間に選んでもらう。
- 点数は耳の代わりではない。報告では「AIの目安」と書き、最後は人間に聴いてもらう。
- 1ラウンドごとに、点数の表を短く人間に知らせる。
- これまで効いたこと（パンク『稲妻ダッシュ』、6.0→8.05）: 録音ギター（`--guitar fsbs-direct`）、歪みを控えめに（ampDrive 0.5）、ギター層を減らす、ドラムとベースを少し下げる。効かなかったこと: マスタリングの種類・広げ・残響。詳細は `docs/sound/listening-toolkit.md`。

## 書き出しの合否表で「つぶれ気味」が出たら（人間の指示 2026-10-11）

`build --wav --master-preset ...` は、PLR・PSR が小さい（つぶれ気味）と、仕上げをやさしくして最大2回、自動でやり直す。警告欄の「再調整しました」を読み、それでも「再調整しても…残りました」と出たら、元の音が原因なので次を直してもう一度書き出す。
- 歪みギターのアンプを見直す（`punk` は高域が割れる。`loudrock`・`crunch` に）。使わない音は `docs/sound/banned-sounds.md`。
- パートの `volume` の合計を 0.7 前後に（全部に同じ係数をかける）。
- 同じ音域に同じギターを重ねすぎない。
- 仕上げは `rock-clean` など、クリップの弱いプリセットに。
やり直しを止めたいときだけ `--no-retune`。
