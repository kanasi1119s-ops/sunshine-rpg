| 2026-09-28 | 中盤以降の育成の幅を出すしくみは、「仲間モンスター」ではなく「職業（極意）システム」を採用する。仲間5人はキャラクターとして固定し、各キャラクターが物語の進行で複数の共鳴術系統（火照・水紋・風唱・地固・光断）を後天的に習得できるようにする。習得のきっかけは「極意書（ごくいしょ）」という各地方で手に入るアイテムとし、第6章前後（霜原・浮嶼あたり）で解禁する想定 | (1)世界観にすでにある「共鳴術5系統」（`bible.md` 4）をそのまま育成システムの土台に使えるため、新規要素を増やさずに済む。(2)仲間モンスターシステムは、捕獲・育成・進化という新しいゲームルールと、モンスター1匹ごとの名前・デザインの用意が別途必要になり、既存作品の「モンスター育成RPG」のお約束に寄りすぎるリスクと、48時間規模の残り開発量を考えると過大。(3)物語の主題（人と人が向き合う、分かり合えなくても手を取る）が仲間キャラクター中心のため、キャラクター育成の幅を広げる職業システムの方が主題との相性が良い | 育成システム全般（`docs/design/growth.md` への追記はフェーズ4・第6章着手時に行う）、`docs/story/bible.md` 8（保留事項の解消） |

| 2026-09-28 | GitHub APIでファイルを直接コミットするとき、日本語テキストは`\uXXXX`のような手作業エスケープに変換せず、プレーンテキストのまま渡す方式に統一する | ローカルの安全装置がPRマージ後の`git pull`を止めることがあり、代わりにGitHub API経由で直接コミットする場面があるが、その際に手作業でUnicodeエスケープに変換して送ったところ、一部の文字を書き間違え、`docs/progress.md`等の文章が文字化けする事故が起きた（例:「遊べる」→「遵べる」）。プレーンテキストをそのまま渡せばツール側が正しく処理するため、以後はエスケープ変換をしない | 記録作業全般（GitHub API経由でのコミット） |
| 2026-09-27 | 「オクトパストラベラーのような見た目にしたい」という要望があったが、特定の既存作品の技法（HD-2D）を直接まねることはしない。「ドット絵×奥行きのある光の演出」という系統だけを参考にし、配色・キャラクターデザイン・演出は完全オリジナルにする | CLAUDE.md 1-1（既存作品のまね絶対禁止、特定の作品・絵柄に寄せない）に反するため。音楽で「特定の作曲家の作風を狙わない」と決めた前例と同じ考え方を絵にも適用した | アート全般（3-8 アート担当の着手時に反映） |
