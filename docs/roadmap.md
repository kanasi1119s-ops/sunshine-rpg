# 工程表

`/rpg-cycle` の実行のたびに、上から順番に2項目以上を仕上げていく。項目は1つ20〜40分で仕上がる大きさにしてある。大きすぎると分かった項目は、着手前にその場で分割してよい（分割したらこのファイルを直す）。

進み具合は `[ ]` → `[x]` で管理する。仮のまま完了扱いにしない（`CLAUDE.md` 1-4）。

## フェーズ1: 基盤（エンジン・歩ける町ができるまで）

- [x] 1-1. プロジェクトの雛形を作る（Vite + TypeScript、`npm install` / `npm run dev` / `npm run build` / `npm test` が通る状態、ディレクトリ構成の決定）
- [x] 1-2. Canvas描画の土台（画面サイズ、PC/スマホ両対応のレイアウト、ゲームループ、デバッグ用のFPS表示）
- [x] 1-3. タイルマップの読み込みと表示（JSON形式のマップデータ→Canvas描画、カメラのスクロール）
- [x] 1-4a. プレイヤーの歩行（キーボード操作、スマホ用の画面ボタン、当たり判定）※マップ切り替えは1-4bへ分割
- [ ] 1-4b. マップ切り替え（出入り口をまたいで別のマップへ移動する仕組み）
- [ ] 1-5. 会話システム（メッセージウィンドウ、文字送り、選択肢、NPCとの会話イベント）
- [ ] 1-6. 台本言語（イベントスクリプト）の設計と実装（`docs/event-script.md` に書式定義、フラグ管理）
- [ ] 1-7. 戦闘システムの土台（フロントビュー画面、コマンド選択UI、ターン順の計算）
- [ ] 1-8. 戦闘のロジック（ダメージ計算、たたかう/じゅもん/とくぎ/どうぐ/ぼうぎょ/にげる、勝敗判定）
- [ ] 1-9. 成長システム（経験値、レベルアップ、能力値の伸び、レベルアップ演出）
- [ ] 1-10. 装備・アイテム・所持品システム（購入、装備、使用、道具屋・武器屋・防具屋UI）
- [ ] 1-11. セーブ・ロード（ブラウザ内複数枠＋オートセーブ、ファイル書き出し/読み込み、バージョン番号）
- [ ] 1-12. Web Audio APIによるBGM再生の土台（波形合成音源、ループ再生、音量/消音設定）
- [ ] 1-13. 効果音再生の土台（決定・キャンセル・カーソル・攻撃・ダメージなど基本SE）
- [ ] 1-14. デバッグメニュー（章ワープ、フラグ操作、レベル変更、無敵、エンカウントなし。本番非表示）
- [ ] 1-15. 基盤の自動テスト整備（戦闘計算・成長・セーブのユニットテスト、CI用のテストコマンド確認）

## フェーズ2: 物語の設計書

- [ ] 2-1. 世界観の設定書 `docs/story/bible.md`（世界の成り立ち・国と地方・歴史・魔法や技術・通貨・地理）
- [ ] 2-2. 主要キャラクター `docs/story/characters.md`（主人公・仲間4〜6人・敵役・黒幕・重要NPC）

- [ ] 2-5. 伏線台帳の土台 `docs/story/clue-ledger.md`（表の形式を作り、構成段階で分かっている伏線を仮登録）
- [ ] 2-6. サブストーリー一覧の骨子 `docs/story/side-stories.md`（章ごとに2〜4本、タイトルと一行あらすじだけでも25本分）

## フェーズ3: 序章を遊べる形にする（見本となる完成品）

- [ ] 3-4. 序章の推理パート1つ（手がかり収集→選択式の問い→評価）
- [ ] 3-5. 序章のBGM（タイトル、町、ダンジョン、通常戦闘、ボス戦の最低5曲）
- [ ] 3-6. 序章の効果音一式と、既存曲目一覧 `docs/sound/tracks.md` の整備
- [ ] 3-7. 序章の本格テスト（3ラウンド）と法務チェック、`main` への統合

## 進め方のメモ
- フェーズ1（基盤）を最優先で最後まで通す。基盤が一通り動くまでは、物語設計（フェーズ2）と並行して進めてよい。
- 章立て（フェーズ4）は、フェーズ3の序章で確立した型をそのまま繰り返す。
- 各フェーズの中で「早く最初から最後まで1本通す」ことを重視し、細部の作り込みは後回しにしてよい。
