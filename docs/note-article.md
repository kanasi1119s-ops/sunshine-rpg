# AIと一緒に、長編RPGを「4日」でどこまで作れたか。作って分かった大変だったこと

（note用の記事案。運営: 旭洋平／サンシャインソフトウェア。投稿前に、数字や表現を確認してください）

---

## はじめに

ブラウザで遊べる、完全オリジナルの長編RPGを作っています。仮題は「sunshine-rpg」です。

- 遊び心地は、王道のコマンド選択式RPG
- 物語は、章をまたいで少しずつ真相に近づくミステリー
- メインストーリーは48時間以内にクリアできる長さ（目標30〜40時間）
- サブストーリー25本以上と、クリア後の裏ボス

ふつうなら何年もかかる規模です。これを、**Claude Code（AI）に「1日6回、4時間おき」に作り進めてもらう**という方法で挑戦しています。私は、方針を決めて、出てきたものを見て、「ここを直して」と伝える係です。

この記事では、作り始めた2026年9月27日から9月30日までの4日間で、何が起きたのか、何が大変だったのかを正直に書きます。

## どうやって作っているか

### 「毎回ゼロから」を前提にした仕組み

AIは、前回の作業をおぼえていません。だから、次の3つを決めました。

1. **`docs/progress.md`（進捗）** に、いまどこまで進んだか、次に何をするかを書く
2. **`docs/roadmap.md`（工程表）** に、20〜40分でできる大きさの作業項目を並べる
3. **実行レポート** を毎回書く

毎回、進捗を読んで、工程表の項目を最低2つ仕上げて、テストが通ったら本線（main）に入れて、次回への申し送りを書いて終わります。会社の引き継ぎ書に近いです。

### 「守ること」を先に書いた

もう1つ大事なのが、`CLAUDE.md` という決まりごとのファイルです。

- **既存作品のまねは絶対にしない**（作品名・キャラ名・呪文名・デザイン・曲・ストーリーの丸写しはしない）
- お金がかかること、公開すること（ストア、ドメイン、SNS、GitHub Pagesなど）は、**必ず人間の承認をもらう**
- 完成度を偽らない（未完成は「仮」と書く）
- 前に作ったものを勝手に壊さない（変えるときは理由を記録する）

AIに長く任せるほど、「やってはいけないこと」を先に決めておく大切さを感じました。

## 大変だったこと

### 1. 「ドラクエ風」と「まねしない」の線引き

一番気をつかったところです。「ドラゴンクエストのような遊び心地」は目指しますが、**名前も見た目も曲も、似せてはいけません。**

実際に、法務チェック（既存作品との似ていないかの確認）で、こんなことが見つかりました。

- 敵役の名前の案「ゲルド」は、ゼルダの伝説の種族名と同じ表記だった → 「ドルン」に変更
- 地名の案「氷華」は、有名な小説・アニメと同じ読みだった → 「霜原」に変更
- 仲間の名前の案「フィア」は、ある有名RPGの人物名に近かった → 「アヤメ」に変更
- 動作確認用に置いた仮の剣の名前が、国民的RPGの代表的な武器と同じだった → 「使い込まれた鉄の剣」に変更
- 仮の敵名「スライム（仮）」も、有名作品のモンスターとして通ってしまう名前だったので改名

悪意がなくても、**AIも人間も「どこかで見た名前」を無意識に出してしまう**ということです。そこで、会話文だけでなくソースコード全体を調べて、既存作品の固有名詞が入っていないかを確かめる自動テスト（`legal-names.test.ts`）を作りました。人の目だけに頼らず、機械でも見張ることにしました。

もう1つ。「あのゲームみたいな見た目にしたい」というお願いを、私自身がしたことがあります。AIは、特定の作品の技法をそのまま使うことはできない、と断りました。代わりに、「ドット絵と光の演出」という系統だけを参考にして、絵の中身はオリジナルにする、という方針に落ち着きました。最初は少しもどかしかったのですが、あとで権利の心配をしなくてよいので、この線引きは正しかったと思います。

### 2. 見た目のクオリティ問題

これは何度も指摘しました。最初のマップは、単色の四角でした。「グラフィックのクオリティが低い」と伝えて、少しずつ底上げしています。

- 会話中の顔グラフィックを追加（色番号のデータ＋パレット方式）
- 顔の絵を、マップ上のキャラにも流用
- 陰影と縁取りを追加、歩行アニメーションを追加
- 草・水・道・木のタイルに、ディザや波の模様を追加
- 「絵の大きさの基準」を決めた（マップ・建物は128×128、ボスや登場人物は256×256）
- 最終的に、マップを歩くキャラクターを**16×32のドット絵に作り直し**

AIは、絵を「想像で文字の並びとして書く」ので、思ったとおりの絵になりません。そこで、**ドット絵エディタ（自作のツール）を作って、絵を見ながら直す**ようにしました。それでも、ここは今も一番の課題です。

無料で商用利用できる素材（ぴぽやさんのタイルなど）は、規約を読んで、記録してから使うルールにしました。有料のものは、私の承認なしには使いません。

### 3. 音楽の方向性が、途中で大きく変わった

最初のBGMの方針は、「16bit風のチップチューン×現代的な音づくり」でした。ところが、私が途中で「レトロ風じゃなくてもいいんだよなー」と言い、方針が変わりました。

その結果、次のことをやりました。

- 合成音だけの再生から、**録音音源（サウンドフォント）での再生**に変更
- 序章〜第6章の既存BGM（23曲）を新しい曲に置き換え、全52曲に
- 曲の「版」を増やした（現代版・PS2世代版・実楽器版）
- 有名フリーBGMを1,000曲測って、「きれいな音」の目安を確かめた

さらに、曲を作る道具のほうが大きくなっていきました。ピアノロール、アンプ、MIDIキーボード入力、WAV書き出し……いつの間にか、**ゲームを作るためのツールが、もう1つの作品になっていました。** 便利ですが、「本編を進める時間」を食べるのも事実です。今日の実行レポートにも、作曲ツールとの接続が失敗して、音の仕上げに手を付けられなかった、と書いてありました。

また、「AIが作曲する画面にAPIキーを入れる」機能は、ブラウザにキーを置く作りが安全確認で止められたため、入れていません。ここは私が判断する番です。

### 4. 「自動テスト」と「実際に遊ぶ」のずれ

自動テストは863件あります。それでも、実際にブラウザで遊ぶ確認は難しいものでした。

たとえば、ヘッドレスブラウザで矢印キーを「ぽん」と押しても、ゲーム側は「フレームごとに押されているか」を見ているので、**押した瞬間が読まれず、キャラが動かない**ことがありました。長い距離を歩く場面のテストが、毎回思いどおりにいかず、代わりに次の工夫をしました。

- セーブデータを直接書き換えて、特定の場面から始める
- デバッグメニューで、マップにワープする
- 序章〜終章を自動で通しプレイして、進行不能がないか確かめるテスト

また、ボスの強さは「自分で遊んで決める」ことができないので、**戦闘を300回自動で行って、勝率を測る**やり方にしました。目安は勝率70〜90%です。第2章のボスは、最初は勝率96%で簡単すぎたので、数値を調整して約85%にしました。

ただ、あとで問題が出ました。途中から仲間が増えたり、ジョブが増えたりして、「Lv1で戦う想定」のバランスは合わなくなりました。そこで、**「想定レベル方式」にバランスを作り直す**ことになりました。作ってから直す手間は、やはり避けられません。

### 5. ミステリーの「フェアさ」を守る

物語のなかで、私が一番こだわりたいところです。ミステリーは、犯人が分かってから読み返して「たしかに手がかりは出ていた」と思えないと、ずるく感じます。

そこで、**伏線台帳**（`clue-ledger.md`）を作って、伏線C-001〜C-020を1件ずつ管理しています。さらに、システムのほうで、こんな決まりを守らせています。

- 手がかりを見つけていないうちは、推理クイズを出さない
- 伏線は、採掘跡を発見してから村長に報告した場合にだけ確定する

これも自動テストで確認しています。AIに物語を書いてもらうときは、「面白さ」より先に「矛盾しないこと」を仕組みにしておくと安心です。

途中で、第7章の裏に新しい戦争の設定を足すなど、物語を大きく広げる変更もありました。そのたびに、`decisions.md`に理由と影響範囲を記録します。「勝手に壊さない」ルールのおかげで、あとから読み返せます。

### 6. 「作りすぎ」と「仮」の管理

4日間で、要素がどんどん増えました。

- サブストーリー32本
- 裏ボス「初源の歪み」、8神、最後の裏ボス
- ジョブ（初期8・上級8・天神・悪神・レジェンド）
- 武具屋、ランダムエンカウント、タイトル画面

広がるほど、「仮」のものも増えます。たとえば次のとおりです。

- サブストーリーのごほうびは、まだ「ごほうび（仮）」の会話だけ
- ボスの絵の一部は図形の仮の絵
- 町の人のセリフの一部は簡易
- **誤字脱字と「読んで面白いか」は、自動ではまだ判断できない**

最後の点は、正直に書いておきます。「面白いかどうか」は、AIも私も、まだ確かめられていません。だから次のステップは、**人間のテストプレイ**です。

### 7. 「人間が決めること」を、AIに越えさせない

AIは、頼めばどんどん進めてしまいます。だからこそ、**お金と公開のところ**は止めています。

- ストアや販売ページの公開、価格設定
- ドメイン、SNS、広告
- 有料素材・有料サービスの契約
- GitHub Pagesの公開（設定ファイルは書くが、有効化は人間がする）

販売に向けた準備（アイコン、利用規約案、説明文など）は、お金を使わない範囲までで止めています。

## 作ってみて分かったこと

1. **AIに任せるほど、「引き継ぎ書」が大事になる。** 進捗・工程表・決定の記録が、そのまま制作の背骨になった。
2. **やってはいけないことを先に書く。** 既存作品のまね、お金、公開。これが最初にあったから、安心して任せられた。
3. **「測れるもの」は機械に測らせる。** 勝率、名前の重複、伏線の順番、進行不能。人の目に頼らずテストにした。
4. **「測れないもの」は、正直に「仮」と書く。** 面白さや絵の魅力は、人間の目がいる。
5. **道具づくりは楽しいが、本編を止める。** 作曲ソフトのように、脇道が大きくなりやすい。

## これから

- 人間によるテストプレイ（セリフの口調、誤字、遊びやすさ）
- 「仮」の絵・曲・ごほうびの本物への差し替え
- 音の仕上げ
- 正式なタイトル決め
- 公開・販売の準備（ここは私が判断します）

引き続き、進み具合をnoteで書いていきます。まだ途中ですが、「AIと一緒に長編RPGを作る」という挑戦の記録として、続きを読んでもらえたらうれしいです。
