## 0. このゲームでの扱い（先に読む）

- **このゲームでは、画像生成AIで絵を作らない。** これまで素材を集めるときも、AIで作った絵は外してきた（権利がはっきりしない、既存作品に似るおそれがある。`docs/assets-credits.md`）。AI生成を取り入れるかどうかは方針の変更なので、**人間の判断が要る**。定期タスクが自分で始めてはいけない。
- それでも、この記事は次の2つの点で役に立つ。
  - **後処理の技法**（マス目にそろえる、色をそろえる、切り抜きの確認）は、手で描く絵や、素材（ぴぽや・ドット絵世界など）を縮小・加工するときにもそのまま使える。
  - **「AIが苦手なこと」は、そのまま「良いドット絵の条件」**になっている。苦手なのは、色をそろえること、1ドットの乱れ、細い指や爪。
- なお、この作業環境にはGPUが無いので、記事の生成の手順はここでは動かせない（記事の筆者は RTX3090・VRAM 24GB を使っている）。

## 1. 記事の作り方の流れ（要点）

1. **大きく描いてから縮める**: 1792×1792px で「1ドットを4×4pxで描く」ように生成し、マス目にそろえて 136×136px にし、128×128px に切り抜く。
2. **マス目にそろえる**: Pixel Snapper で、にじんだ・ずれたドットを、まっすぐなマス目に置き直す。
3. **色を減らす**: 必要なら6色ほどまで減らして、色のムラをなくす（Pillow で減色）。
4. **手で直す**: Aseprite で切り抜き、欠けた角・爪を短く描き直し、色のずれを直す。
5. **動きのコマ（差分）**: 1枚ずつ作ると色がばらつくので、「全部のポーズを1枚にまとめて作る」か「動画から切り出す」ほうがよい。立ち止まり・歩きは成功しやすく、走り（とくに指）は崩れやすい。

生成の指示（プロンプト）では、避けるものとして次を並べていた。
- 落ち影、ぼかし、3D、アンチエイリアス、グラデーション、質感（テクスチャ）
- 被写界深度、アニメ調、今風のカートゥーン、「かわいい」「ちびキャラ」
- ゆがみ・遠近、文字、透かし

ここから分かるのは、**ドット絵らしさを壊すのは「なめらかさ」と「遠近」**だということ（第3節の1）。

## 2. 記事の筆者がいちばん苦労したこと: 色

- 「4色で」と指示しても、実際には**100色ほどの近い色が隠れて混ざる**（見た目は4色でも、ファイルの中の色の数はずっと多い）。
- 生成するたびに**色の組み合わせ（パレット）が変わる**ので、同じキャラのコマどうしで色が合わない。
- 筆者の結論は「ほかの問題はほぼ解決したが、色は未解決」。

## 3. このゲームの絵づくりに生かすこと

既存の手引き（`pixel-art-notes.md`・`pixel-character-guide.md`）に足す内容です。

1. **なめらかさを入れない**
   - グラデーション・ぼかし・外周のアンチエイリアス・落ち影・質感の描き込みは使わない。
   - 遠近（奥が小さくなる）も使わない。見下ろしのマップは、正面・横・後ろの3方向を、遠近なしで描く。
   - これまでの「外周にアンチエイリアスをかけない」「ピロー陰影を避ける」と同じ方向。
2. **パレットは「描く前に」決めて、全部のコマで使い回す**
   - キャラごとに色の組（12色以内、`pixel-character-guide.md`）を最初に決める。
   - 4方向×3コマ（V-2〜V-5）は、その組だけで描く。
   - 色を足したくなったら、組そのものを直す。直したら全コマに反映する。
3. **書き出したら、色の数を数える**
   - 見た目が同じでも、近い色が混ざっていることがある（記事の「隠れた100色」）。
   - 絵を作ったり縮小したりしたら、ファイルの中の色の数を数えて、決めた組からはみ出していないか確かめる。数え方の例は第4節。
4. **動きのコマは、1枚のシートにまとめて作る**
   - 4方向×3コマを1枚の中で並べて描くと、色・大きさ・足元の高さがそろいやすい。
   - 1コマずつ別に作ると、ずれやすい。
5. **崩れやすい所を重点的に見る**
   - 走り・振りかぶりなどの大きな動き、指・爪・角・尻尾の先は崩れやすい。
   - 歩き（1→2→3→2）と立ち止まりは比較的やさしい。崩れやすい所から先に確かめる。
6. **縮小・切り抜きのあとは、はしを確かめる**
   - 切り抜きで、角・爪・武器の先が欠けやすい（記事では128×128の切り抜きで欠けた）。
   - 描くときはキャンバスの端に1〜2ドットの余白を残し、切り抜いたら外周を見直す。
7. **素材を縮小するときは、整数倍で、最も近い色で縮める**
   - 32×32の素材（ぴぽや・ドット絵世界）を16pxにするときは、ちょうど半分にする。
   - 色を混ぜない縮小（最近傍）を使い、そのあとマス目と色をそろえる。
   - 縮小で生まれた中間色は、決めたパレットの色に置きかえる。
8. **背景は単色で作ってから透過にする**
   - 白一色など、キャラに使わない色を背景にして描くと、透過にするときに外周が汚れにくい。

## 4. 色の数を数える・パレットに合わせる（Python の例）

この作業環境には Pillow があるので、次のように確かめられる（例。必要になったら `tools/pixel-art/` に道具として置く）。

```python
from PIL import Image
im = Image.open("hero.png").convert("RGBA")
colors = {c for c in im.getdata() if c[3] > 0}      # 透明でない色
print(len(colors), "色")                             # 決めた色数（例: 12）を超えていないか

# 決めたパレットの最も近い色に置きかえる（中間色の掃除）
pal = [(0x1a, 0x1c, 0x2c), (0x5d, 0x27, 0x5d), (0xb1, 0x3e, 0x53)]  # 例
def nearest(c):
    return min(pal, key=lambda p: sum((a - b) ** 2 for a, b in zip(p, c[:3])))
out = Image.new("RGBA", im.size)
out.putdata([(*nearest(c), 255) if c[3] > 127 else (0, 0, 0, 0) for c in im.getdata()])
out.save("hero_fixed.png")
```

- 半透明は「表示する／しない」の2つにそろえる。ドット絵の外周に半透明を残さない。

## 5. Pixel Snapper（マス目にそろえる道具）について

- **何をするか**: にじんだ・大きさがばらばらなドットの絵から、ドットの大きさを自動で見つけ、まっすぐなマス目に置き直して、色の数を減らす。
- **ライセンス・作り**: MITライセンス、Rust製。コマンドとブラウザ版（WASM）がある。
- **主な設定**:
  - 色の数: 既定 16
  - `--pixel-size`: ドットの大きさを手で指定
  - `--palette`: 使う色を16進数で並べて、その色だけにする
- **このゲームでの使い道（候補）**: 素材を縮小・加工したあとの「マス目と色をそろえる」仕上げ。`--palette` でキャラのパレットを指定すれば、第3節の2・7をまとめて行える。
- 使うなら、`cargo install spritefusion-pixel-snapper` で入れる（Rust が必要）。道具なので素材の記録は不要だが、どの絵に使ったかは作業の記録に書く。**まだ入れていない。**
