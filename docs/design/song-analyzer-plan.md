# 曲の分析ソフト（学習用）と音源づくり — 構想（2026-11-16・案。まだ作っていない）

人間（2026-11-16）:「曲聴いたらなんの楽器を使ってるかわかって、コードもわかって、音の種類もわかって、強弱、ジャンル、全てわかる分析ソフト作ろうか。ちょっと曲作りが単調すぎて、学習の為のソフトにしよう。で、音源を作れる様なソフトにもしよう。ちょっと構想をまず練って」

## 1. ひとことで

曲のファイルを入れると「その曲がどう作られているか」のカルテ（数字と図）が出て、自分の曲と並べて「どこが違うか」が分かるソフト。カルテから、作曲ソフトの型（リズム・重ね方・強弱の付け方）と、音色（シンセの音）を作る。

## 2. 入れるもの → 出てくるもの

| 分かること | 中身 | 当たりやすさ（見こみ） |
|---|---|---|
| テンポ・拍子・小節の位置 | 拍と小節の頭 | 高い |
| 構成 | 前奏・Aメロ・サビなどの区切りと長さ、くり返し | 中〜高 |
| 強弱 | 場面ごとの音量・音の厚み・低音〜高音のバランス・左右の広がり、盛り上がりの曲線 | 高い（測るだけ） |
| 楽器 | 歌・ドラム・ベース・ギター・ピアノ・そのほか、に分けて、いつ鳴っていていつ休むか | 大きな分類は高い。細かい楽器名は中 |
| ドラム | キック・スネア・ハイハットの位置と強さ、手数、アクセント、フィル | 中〜高 |
| ベース | 音の高さとリズム、根音との関係、休み方 | 中〜高 |
| コード | 和音の名前と変わる位置、調、度数 | ふつうの和音は中〜高。テンションや転回は低〜中 |
| 歌・主旋律の形 | 音の長さ・休み・跳び方・食い方・音域（旋律そのものは保存しない） | 中 |
| 音の種類 | 歪みの深さ、明るさ、立ち上がりと余韻、ゆれ、残響の長さ、シンセの波形の性格 | 中（「こういう性格の音」まで。同じ音そのものは割り出せない） |
| ジャンル・雰囲気 | 近いジャンルと雰囲気のことば | 中（目安） |

## 3. しくみ（3段）

1. **分ける**: 曲を、歌・ドラム・ベース・ギター・ピアノ・そのほかの音に分ける（音源分離）。
2. **測る**: 分けた音ごとに、拍・音の高さ・強さ・音色を測る。全体からは、構成・コード・強弱・ジャンルを測る。
3. **まとめる**: 「曲のカルテ」（1曲1枚の画面と、機械が読める JSON）にする。

すでにある道具（`tools/audio-check/` の和音・リズム・ステム・音質の点数、参考の音の測定）を土台にして、足りないもの（音源分離・構成・楽器の出入り・ドラムの書き起こし）を足す。

## 4. 学習への使い方（ここが本体）

- **差分の表**: お手本のカルテと自分の曲のカルテを並べて、違いが大きい順に出す（例:「お手本はAメロでギターが休む。自分は鳴りっぱなし」「お手本はサビ前に1拍無音。自分はない」）。
- **型の取り出し**: ドラムの型・ベースの動き方・楽器の出し入れの順番・強弱の曲線を、作曲ソフトの部品（`FEEL` のような型）として保存する。旋律・歌詞・コード進行の丸写しは保存しない。
- **ためる**: 何曲も入れると、ジャンルごとの「ふつう」と「その曲だけの特徴」が分かる。作る前に「今回はどの特徴を使うか」を選べる。
- **確かめる**: 自分の曲を書いたあと、同じ道具で測って、ねらった特徴が出ているかを見る（今は点数しか見ていない）。

## 5. 音源づくり（3つの道）

| 道 | 何をするか | 使える場面 |
|---|---|---|
| A. 測って、シンセで作る | お手本の音の性格（波形・明るさ・立ち上がり・余韻・ゆれ）を測り、Surge XT で近い音を作って音源にする | どの曲からでも。録音そのものは使わない |
| B. 録音から切り出す | 単音を切り出して音源にする | 自分の録音・自分で作った音・規約で認められた素材だけ |
| C. エフェクターの並びを作る | 歪み・EQ・残響の数字を測って、作曲ソフトのエフェクターの設定にする | どの曲からでも |

## 6. 守る線

- 市販の曲から音を切り出して音源にしない（録音そのものの流用になる。CLAUDE.md 1-1）。市販の曲からは A と C だけ。
- 保存するのは「作り方の特徴」と統計。旋律・歌詞・1曲ぶんのコード進行は保存しない。
- 規約で AI の学習に使えないと書かれた素材は入れない（2026-11-15 に確かめた2つのサイトなど）。
- 使う分析の部品は、ライセンスを1つずつ確かめてから入れる（研究用・非商用だけの部品がある）。有料のものは人間の承認がいる。
- 分かったふりをしない: 当たりやすさが低い項目は「たぶん」と表示する。

## 7. 作る順番（案）

| 段 | 作るもの | できるようになること |
|---|---|---|
| 1 | 分ける＋拍・構成・強弱・楽器の出入り | 「いつ・何が鳴って・何が休むか」「強弱の曲線」が1曲ぶん見える。自分の曲との差分が出る |
| 2 | ドラム・ベース・コードの書き起こし | リズムの型とベースの動き方を、作曲ソフトの部品にできる |
| 3 | 音の種類の測定 → シンセの音づくり（道 A・C） | お手本に近い性格の音を、音源として足せる |
| 4 | カルテをためる画面・ジャンルごとのまとめ・作曲ソフトへの取りこみ | 作る前に特徴を選び、作ったあとに確かめる流れができる |

## 8. まだ決まっていないこと

- どんな曲を入れるか（自分で作った曲・買った曲のファイル・フリーの曲）。これで守る線の細かい所が変わる。
- どこで動かすか（パソコンのアプリ／ここ＝クラウドで私が使う道具）。パソコンは GPU なしなので、1曲の分析に数分かかる見こみ。
- 私（Claude）は音が聞こえないので、当たっているかどうかは、答えの分かっている曲（自分の曲の JSON）で先に確かめる。

## 9. 決まったこと・進み具合（2026-11-16）

- 人間:「１曲分のコード進行は保存しなくていいですが…1部のコード進行は保存してください。また旋律は保存しなくても、アレンジできるように学習はしてください。段1作りましょう。曲はフリーのボカロ、ロック、ダンス、エレクトロニクス、ファンク、KPOP、jpop、メタル、から学びましょう。」
  - 短いコード進行（一部）は保存する。旋律そのものは保存しないが、形（長さ・休み・跳び方・食い方・音域）は学ぶ。→ 段2で作る。
- お手本の出どころ: 人間「とりあえず1で」＝ **本人（作者・レーベル）が自由なライセンスで出していると確かめられる曲だけ** で進める。J-POP・K-POP は、そういう曲がほぼ無いので、解説記事とこれまでの統計で補う。
  - Internet Archive は「CC」「パブリックドメイン」と書いてあっても、他人が市販の曲を勝手に上げたものがある（確認ずみ）。だから、ネットレーベルの集まり（collection: netlabels）に入っていて、ライセンスが CC BY・CC BY-SA・CC0 の作品だけを取る（`tools/song-analyzer/collect_ia.py` がこの条件を確かめる）。
- 段1: できた（`tools/song-analyzer/`。当たりやすさは README）。
- お手本 13曲（ロック3・メタル2・ファンク2・ダンス2・エレクトロニクス2・ボカロ2）と、自分の曲4曲（13・14・15・16）のカルテを `docs/sound/karte/` に置いた。まとめは `docs/sound/karte/summary.md`。
- **分かったこと: 段1の粗い数字（楽器の出入り・休み・音量の幅・場面の長さ・ドラムの手数）では、自分の最近の曲はお手本の幅にほぼ入っている。** 幅の外は「伴奏の休み」「和音の楽器の休み」だけで、それも自分の方が多い。つまり「単調」の原因は、段1で見える所ではなく、もっと細かい所（リズムの型・ベースの動き・和音・旋律の形・音色）にありそう。→ 段2・段3が要る。
- 気をつけること: お手本はネットレーベルの曲で、有名なプロの曲ではない。数も少ない（1ジャンル2〜3曲）。
