# 毎日10曲を最後まで作る（完全版プロンプト・Claude Code用）

PC の作業フォルダ（C:\Users\fujik\Music\music-tools）で Claude Code を開き、下の枠の中をそのまま貼る。設計図づくりから、作曲・歌声・仕上げ・確認・報告までを、確認なしで最後まで進める。

## ▼ここから貼る▼

あなたは、プロのレベルの曲を毎日10曲、最後まで仕上げる制作担当（音楽プロデューサー兼作詞家兼エンジニア）です。確認を求めず、下の手順を最初から最後まで実行してください。作業フォルダは C:\Users\fujik\Music\music-tools です。

## ゴール
今日の日付（D = yyyy-MM-dd）で、4〜5分の曲を10曲、完成させる。
完成の条件:
- inbox\D\ に、曲ごとの WAV・MIDI・.report.json・index.md がある（歌入りの曲は .vocal.json と歌声つきのWAVも）。
- out\D\ に、音量を整えた WAV と MP3 が10曲ぶんある。
- 各曲が「確認の基準」（手順6）を満たす。満たせない曲は、原因つきで最後に報告する。

## 使う道具
1. サンシャイン作曲ソフト: `node %USERPROFILE%\sunshine-rpg\tools\composer\make.mjs`。文章から4〜5分の曲を自動で組み立てる。無料。歌詞（ひらがな・カタカナ）を渡すと女声（VOICEVOX 波音リツ）で歌う。
2. `vocal_tool.py`（歌声をつける）、`song_tool.py`（音量調整・MP3化）、`start_voicevox.bat`（歌声エンジンの起動）。
3. ACE-Step・Suno は、今日の作業では使わない（設計図の JSON は、そのまま貼って使える形にしておく）。

## 作曲ソフトの得意・不得意（これに合わせて設計する）
- 読み取れる曲調: メタル、デスメタル、ハードコア、プログレメタル（7拍子）、ロック、ダンスロック、クリーンダンス、エレクトロ、J-POP、ジャズ、R&B、フォーク、クラシック、バロック、エピック、宇宙・自然・カフェ・ミステリー系、フォンク、サンバ。
- 味つけ（prompt に書く）: loud（ラウド。リズムギターを左右に倍にする）、orchestra（弦・ブラス・合唱・ティンパニ）、wagakki（琴・三味線・尺八・太鼓）。orchestra と wagakki は4拍子の曲だけ（7拍子のプログレには付けない）。
- 自動で入るもの: モチーフ旋律、2回目のAメロは別の旋律、ポップ・ロック・エレクトロ・壮大系はラスサビで全音上がる転調、サビ頭のクラッシュ、ブリッジ後のストップタイム。
- 歌声は女声。きれいな歌声で成り立つ曲（メロディアス、プログレ、ラウドロック、ダンス×ロック、ロック×オーケストラ、ロック×和楽器、J-POP など）に歌をつける。デスメタル・ハードコアなど、グロウルやシャウトが主役の曲は歌なし（インスト）。10曲のうち歌入りは4〜6曲。
- 限界: 旋律は規則から作るので似た雰囲気になりやすい。耳での確認はあなたにはできない。

## 手順

### 0. 準備の確認（1分で済ませる）
- 次が使えるか確かめる: `node -v`、`ffmpeg -version`、`python --version`、`%USERPROFILE%\sunshine-rpg\tools\composer\make.mjs` の存在、`vocal_tool.py`・`song_tool.py`・`start_voicevox.bat`。
- 足りないものがあれば、`setup_windows.ps1`・`setup_composer.ps1`・`setup_voicevox.ps1` のうち該当するものを実行して直す。直せなければ、その旨を報告して、できる範囲（例: 歌なしの曲）で先へ進む。
- 日付 D を決め、inbox\D と out\D を作る。

### 1. 設計図を作る（songs.json）
- 今の songs.json は songs.backup.json に退避してから、新しい songs.json を書く。
- 最近の曲名（inbox の過去の *.report.json の title）と重ねない・似せない。ジャンルの組み合わせは前日までと変える。
- ジャンルをばらけさせる。同じ曲調を3曲以上並べない。例: メロディアスメタル／プログレ／ロック×和楽器／ラウドロック／ダンスロック／ロック×オーケストラ／J-POP／ハードコア／テクニカルデスメタル／エピック。
- 曲ごとに bpm・key_scale（例 "E minor"）・time_signature（例 "4/4"）を決める。audio_duration は 240〜300（秒）。
- prompt は英語のキーワード中心で具体的に: ジャンル、味つけ（loud / orchestra / wagakki）、雰囲気、楽器、テンポ、キー、歌の有無（female vocal / instrumental）。**既存の曲名・アーティスト名・バンド名は書かない。**
- 歌入りの曲は歌詞を2種類書く（"voice": "波音リツ" も入れる）:
  - lyrics: 漢字まじりの表示用。
  - lyrics_kana: ひらがな・カタカナだけの歌い用。
    - `[verse]` `[bridge]` `[chorus]` の見出しで区切る。1つのまとまりは4行。
    - 1行は8〜14音（150 BPM 以上は8〜11音）。「きゃ」は1音、「っ」は数えない。
    - 助詞は発音どおり（は→わ、へ→え、を→お）。「ー」「っ」「ゃゅょ」は使ってよい。漢字・英字・数字は使わない。
    - Aメロ2〜3つ、Bメロ1〜2つ、サビ1つ（サビは毎回歌う）。
    - 歌詞は完全にオリジナル。実在の歌詞・フレーズは使わない。サビは短く覚えやすい言葉に。
- インスト曲は lyrics / lyrics_kana / voice を書かない。
- **検査**: 次を自分で確かめる（通るまで直す）: 10曲ある・曲名が重ならない・title と prompt がある・lyrics_kana に ひらがな・カタカナ と見出し以外がない・[chorus] がある・JSONの文法が正しい。JSON は `python -c "import json;json.load(open('songs.json',encoding='utf-8'))"` で読めることを確認する。

### 2. 曲を作る
- `node %USERPROFILE%\sunshine-rpg\tools\composer\make.mjs batch songs.json --wav --out inbox\D`（1曲 約2〜3分。全体で30分前後）。
- 失敗した曲は、エラーを読んで原因を直し、その曲だけ `--only 番号` で作り直す。同じ失敗を3回くり返したら、その曲は飛ばして先へ進み、最後に報告する。

### 3. 機械的に確かめる（耳の代わり）
- 各曲の .report.json の audio 欄を読む。基準:
  - 長さ 4:00〜5:00（240〜300秒）
  - 音量 -17〜-13 LUFS
  - トゥルーピーク -1 dB 以下
  - 警告（高音が弱すぎる・低音が強すぎる・2〜4kHz が強すぎる）が出ていない
- 基準から外れた曲は、種を変えて作り直す（`make.mjs one --title … --prompt … --variations 3 --wav`）。3つの中で基準にいちばん近いものを採る。それでも外れたら、そのまま採り、最後に「基準外」と報告する。

### 4. 歌声をつける（歌入りの曲だけ）
- `inbox\D\*.vocal.json` があるときだけ。`call start_voicevox.bat` でエンジンを起動し、`python vocal_tool.py batch inbox\D` を実行する。
- 起動できない・声の生成に失敗したときは、その曲は歌なしのまま先へ進み、最後に報告する（歌だけ後でやり直せる）。

### 5. 仕上げる
- `python song_tool.py batch inbox\D -o out\D`（音量調整・MP3化）。元のファイルは上書きしない。

### 6. 確かめて、足りなければ直す（最大3回）
- out\D の WAV と MP3 が10曲ぶんあるか数える。足りない曲は、原因（手順2〜5のどこで止まったか）を調べて、その曲だけやり直す。
- inbox\D\index.md と credits.txt（歌入りの曲があるとき）が出来ているか確かめる。

### 7. 報告する（日本語、簡潔に）
- 完成した曲数 / 10。
- 曲ごとの表: 番号・曲名・ジャンル・BPM・キー・長さ・LUFS・歌あり/なし・基準の合否。
- うまくいかなかった曲と、その理由・次にやること。
- 歌入りの曲のクレジット（credits.txt の内容）。
- 最後に必ず書く: 「耳での確認は未実施。公開前に、人間が聴いて選ぶこと。歌入りの曲は『VOICEVOX:波音リツ』のクレジットが必要。」

## 守ること
- 既存の曲・歌詞・アーティスト名のまねをしない。歌詞は完全にオリジナル。
- 有料のサービス・ソフトを新しく契約しない。外部サービスに公開・投稿しない。
- 元ファイルを上書きしない（出力は songs.json〈退避あり〉・inbox\D・out\D・logs だけ）。
- 迷ったら質問せず、いちばん無難な方を選んで進め、選んだ内容を最後の報告に書く。
- 完成していないものを「完成」と言わない。できなかったことは、そのまま書く。
