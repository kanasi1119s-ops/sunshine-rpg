# 法務役の学習メモ（2026-10-02）
**注意**: 検索結果の要約が中心（本文を読めたページはほぼない）。「一般」「提案」「補」は出典で確かめていない一般的な目安。数値は出発点で、最後は耳（と人間の確認）で決める。既存曲の旋律・曲名は例に使わない（`CLAUDE.md` 1-1）。

法律の助言ではなく、一般論の整理。条文・判決文の原文は読めていない。**迷ったら専門家（弁護士・弁理士・管理団体）に相談する。**

## 基本原則
**確認できた事実（検索要約。原典での再確認が必要）**
- 侵害の要件は**類似性と依拠性の両方**。偶然似ただけ（偶然の暗合）は侵害にならない（最高裁昭和53年9月7日判決が依拠の代表例）。
- 音楽の類似性は、創作的表現が共通するかで見る。曲ごとに「表現上の本質的な特徴」がどこにあるか（旋律・和声など）を検討。旋律のある通常の曲では旋律が相対的に重視されるという整理（記念樹事件の解説）。
- アイデア（作風・雰囲気）や創作性のない部分だけが共通する場合は、類似性が否定される（文化庁の考え方の要約）。
- 保護期間は、2018年12月30日のTPP11発効以降、原則として著作者の死後70年（無名・変名・団体名義は公表後70年）。消滅した権利は復活しない。
- 包括契約は基本的に著作権（作詞・作曲）だけが対象で、原盤権は含まれない。CD・サブスク音源をそのまま流すと、著作権・原盤権・実演家の権利が関係する。
**一般的な実務知識（出典なし）**
- 著作物は「思想・感情の創作的表現」。権利は 著作権・著作者人格権・著作隣接権。旋律だけでなく、和声進行・リズム・編曲の組合せも創作性の対象になり得る。ありふれたコード進行・スケール・定型リズムは単独では保護されにくい。
- 依拠は、既存曲を知っていた（アクセスがあった）ことから推認される。無意識の依拠でも問題になり得る。
- 権利制限（私的使用・引用など）は、ゲームの商用BGMには通常あてはまらない。
- 「似ていないつもり」では足りない。比較と記録で説明できる状態にする。

## 公開前チェックリスト
1. 曲ごとの出自を決める（自作・外部素材・AI支援）。記録する。
2. 旋律の照合: 主旋律を音名と音価で書き出し、有名曲と比較する。冒頭4小節・サビ・特徴的な跳躍や反復に注意。
3. 参考にした曲がある場合は「雰囲気（テンポ・編成・ジャンル）」だけを参考にする。旋律・コード進行・リズムパターンの組合せは写さない。
4. ベース・コード進行・リズムの組合せが既存曲と重ならないか確認。ありふれた進行でも、旋律とセットで一致したら要注意。
5. 外部素材は規約全文を読んでから使う。**規約が読めない素材は使わない**。
6. 素材の「再配布禁止」と「ゲームへの組み込み配布の可否」を分けて確認。
7. クレジットが必要な素材は、ゲーム内のクレジット画面かREADMEに表記。
8. AI生成の要素を使うなら、ツールの規約（商用利用・出力の権利）と、実際に人が何をしたかを記録。
9. 効果音が既存作品の音に似ていないか確認。
10. 配信・動画投稿の方針を、説明書やREADMEに書く。
11. 「仮の曲」は、ゲーム内と progress.md の両方で仮と分かるようにする（1-4）。

## ライセンス早見表（一般論。必ず各素材の規約原文を確認）
| ライセンス | 商用 | 改変 | 条件・注意 |
|---|---|---|---|
| CC0 | ○ | ○ | クレジット不要。ただし素材の出所が正しいか（権利者本人の公開か）は別に確認 |
| CC BY | ○ | ○ | クレジット必須（題名・作者名・ライセンス名とリンク・改変の有無） |
| CC BY-SA | ○ | ○ | 改変物を同じ条件で公開する義務。ゲーム全体に波及するか解釈が分かれるため原則避ける |
| CC BY-NC | × | | 有料・広告つきのゲームには使わない |
| CC BY-ND | | × | アレンジ・ループ加工ができないので実質不向き |
| MIT | ○ | ○ | 著作権表示と許諾文の同梱が必要。FluidR3 は MIT |
| GPL | | | 音源・データを組み込む場合の波及範囲は解釈が分かれる。原則避け、使うなら専門家に確認 |
| 独自規約 | | | 例: GeneralUser GS は私的・商用の音楽制作に制限なく使えるとされるが、一部サンプルの由来が作者にも完全には分からないという注意書き。原文の確認が必要 |
- MIT・CC0・CC BY は組み合わせやすい（クレジットは集約して表記）。SA・GPL・NC は条件が衝突しやすい。
- 「SoundFontを使って自分で作曲した曲」の権利と、「SoundFontそのものを配る」ことは別。ゲームに音源ファイルを同梱するなら再配布条項の確認が必要。WAV等に書き出して使う場合も、規約が書き出し物の扱いを認めているか確認する。

## 記録に残す項目と書式
**曲ごとの記録**: 曲ID／曲名／作成日／作成者（人間 or Claude Code 等）／仮or完成／作り方（自作・AI支援〈ツール名・モデル名・日付・指示内容の要約〉・人間の修正点）／参考にした曲（なし or 雰囲気の参考のみ。曲名と参考にした点・写していない点）／旋律照合（実施日・比較対象・結果・担当者）／使用音源・素材（素材記録へのリンク）。
**素材の記録**（docs/assets-credits.md）: 素材名／入手元URL／入手日／作者／ライセンス名と規約URL／**規約の保存（原文を assets-src/ に保存。規約ページが消えても分かるように）**／商用可否・改変可否・クレジット要否・再配布可否・ゲーム組み込み可否・素材そのものの再配布禁止の有無／クレジット文面と表記場所／判断（使う or 使わない、理由）。
クレジット文面の例: 「音源：〈素材名〉 by 〈作者〉（〈ライセンス名〉）〈URL〉。改変：リズム調整」

## 専門家に相談すべき基準
- 照合で、有名曲と旋律が数小節にわたり似ていると感じたら、公開前に差し替えるか相談する。
- AI生成のメロディが既存曲に似ていた場合、またはAIツールの学習元や規約が不明な場合。
- GPL・CC BY-SA・独自規約の波及や互換性が判断できない場合。
- 有料販売・ストア公開・広告など収益化に進む前（人間の承認が必要な事項でもある。CLAUDE.md 1-2）。
- 他者から指摘・警告を受けた場合（自分で返答せず、まず記録を保全して相談）。
- 管理団体の信託契約を検討する場合、またはゲームに管理曲を使う場合。

## AI関連の一般論
- **日本**（文化庁「AIと著作権に関する考え方」の要約）: AI生成物が既存著作物に類似し、かつ依拠が認められ、権利制限の対象外なら、侵害になり得る。学習段階でその著作物にアクセスがあれば依拠は基本的に推認される。学習データに含まれないなら偶然の一致として依拠は否定される。AIが自律的に生成したものには原則著作権が生じない。人がAIを道具として使い創作的寄与を加えた場合は別。
- **米国**（著作権局2025年報告 Part 2）: 現在の技術ではプロンプトだけでは作者にならない。人間が表現を決めた部分（選択・配置・修正）は保護され得る。個別判断。
- **EU**（欧州議会2025年調査）: 完全なAI生成物は「人の知的創作」の要件を満たさない。人が形作ったAI支援作品は保護され得る。
- **本プロジェクトへの示唆**: AI支援曲は、人間がどこを決めたかの記録がないと、自分の権利の主張も難しくなる。記録を残す。

## 管理団体（JASRAC等）と配信
- 著作権は創作で自動的に発生し、登録は不要。信託すると権利が団体に移り、自作品の利用でも原則使用料が必要になり得る（ゲームソフト向けの特例規定あり）。自作曲だけをゲームに使い信託しないなら、届出は通常不要（一般論）。他者の管理曲や市販音源を使うなら許諾が必要。
- ゲーム配信・動画投稿: ゲームごとの利用ガイドラインに従うのが基本。自作・自社管理のBGMだけなら、配信を許可する方針と、禁止したい範囲（BGM単体の販売など）を説明書に明記する（提案）。外部素材のBGMがある場合、その素材の規約が配信を妨げないか確認。
- 不確かな点: 判例の細部、各ライセンスの原文、JASRACの最新の区分、文化庁文書の原文は未確認。EUの Like Company v. Google（C-250/25）は2026年末ごろに判断が出る可能性があり、状況が変わり得る。
