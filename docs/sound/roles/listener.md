# 聴取係（QA）役の学習メモ（2026-10-02）
**注意**: 検索結果の要約が中心（本文を読めたページはほぼない）。「一般」「提案」「補」は出典で確かめていない一般的な目安。数値は出発点で、最後は耳（と人間の確認）で決める。既存曲の旋律・曲名は例に使わない（`CLAUDE.md` 1-1）。

## 原則
1. 聞こえ方は環境で変わるので、**実機・実文脈（ゲーム内）で確かめる**。ループの継ぎ目のクリック、場面の切り替え、音量バランスを聴く。
2. ループは、終わりと始まりがつながり前後に無音がない。端は0で始まり0で終わる。
3. 音量は大きすぎると歪む。効果音が曲や会話を覆わないか、音量スライダーとミュートが効くかも見る。
4. 飽きはループの長さに左右される。1つの曲は5分以上でループが望ましい／約90〜120秒の変化なしの繰り返しで気づかれる／基本の曲は最低60秒で90〜120秒が望ましい、という説がある（根拠は記事ごとにまちまち。目安）。
5. 聴取テストは比較条件をそろえる。A/B・ABXは音量差が結果を大きく曲げる（ABXは1/3dB未満の精度が要るという記述）。順序はランダム。周りの人の反応が答えに影響する。
6. MUSHRA（音質の細かな評価法）は基準音と3.5kHz・7kHzのローパス版の「アンカー」を混ぜ、経験のある聴取者15〜20人が推奨。**本プロジェクトの規模では厳密なMUSHRAは不要**。少人数・非専門家なら「5段階評価＋自由記述」で足りる（提案）。
7. プレイテストは**観察が先、質問は誘導しない**。「操作に迷った？」でなく「次に何をする？」。感じ方を決めつけず本人に語らせる。
8. 聴覚への配慮: 重要な情報を音だけで伝えない。字幕や視覚の合図を併用し、音量や音の種類を個別に調整できるようにする。

## 聴取依頼のテンプレ（人間の聴き手に渡す文）
```
【お願い】曲「◯◯」（場面: ◯◯）を聴いて感想をください。上手・下手の評価ではなく、感じたままで大丈夫です。
聴き方: 機器は【イヤホン/スピーカー/スマホ内蔵】、音量は【普段聴く大きさ】。画面は見ずに1回、ゲーム内で1回聴く。曲は最後まで（または2周）聴く。
Q1 聴いて最初に思い浮かんだ場面や気持ちを、一言で。
Q2 この曲は【町/戦闘/洞窟…】に合っていますか。5(ぴったり)〜1(合わない)
Q3 聴きやすさ 5(心地よい)〜1(つらい)。1〜2なら、どのあたり(何秒ごろ・どの楽器)か。
Q4 耳に痛い、うるさい、こもる、遠い、と感じた所はありますか。あれば時間と言葉で。
Q5 メロディを口ずさめますか。（記憶に残るかの目安）
Q6 2周目で「また同じだ」と感じ始めた時間は。気にならなかったなら「なし」。
Q7 つなぎ目（曲の終わり→始まり）で、ぶつっと途切れる・間が空く・音が跳ぶことはありましたか。
Q8 ほかの音（効果音・声・他の曲）とのバランスは。曲が大きすぎ・小さすぎ・ちょうどいい。
Q9 1時間聴き続けたとして、疲れそうですか。(はい/いいえ/わからない)
Q10 自由記述。直すなら1つだけ何を変えたいか。
```
- A版/B版を比べるときは、順番を入れ替えた2通りの依頼書を人によって使い分ける／両方の音量をそろえて書き出す／「どちらが好きか」と「理由」を聞く。

## 感想→直す点の変換表（日本語の対応は意訳。周波数は目安で確定診断ではない）
| 聴き手の言葉 | 想定される原因 | 作業指示の例 |
|---|---|---|
| 耳に痛い、キンキン、刺さる | 2.5〜5kHz付近が強い、高音の重なり | 高音の楽器の音量を下げる、音域を下げる、重ねを減らす |
| こもる、ぼやける | 200〜500Hzのたまり、高音が足りない | 低中音の楽器を減らす、音域を分ける、明るい音色を足す |
| 箱の中みたい | 300〜800Hz付近が強い | 中音の厚みを減らす |
| 軽い、安っぽい、シャリシャリ | 低音が少なく高音が多い | ベースを足す、高音を引っ込める |
| 低音がうるさい、ブーンと響く | 60〜250Hzが強い | ベースの音量を下げる、音域を整理する |
| うるさい、ごちゃごちゃ | 同時に鳴る音が多い、音量が大きい | パートを間引く、全体を小さくする |
| 迫力がない、地味 | 強弱の差が小さい、低音が少ない | サビで音を厚くする、ドラムを足す |
| すぐ飽きる、また同じ | ループが短い、変化がない | 長くする、途中で変化を入れる（60〜120秒以上が目安） |
| 途切れる、間が空く | 無音の余白、ループ点のずれ | 前後の無音を削る、小節の長さを見直す |
| ぷつっと音がする | 0でない所で切れている | 切り目を0にそろえる、短いフェード |
| 曲が急に大きい・小さい | 曲ごとの音量差 | 音量をそろえる（`bgm-trim.ts`） |
| 場面に合わない | 速さ・調・楽器と雰囲気のずれ | テンポ・調・音色の候補を変える |

## QAチェックリスト
**共通（曲ごと）**: 開始から終了まで通して再生し、継ぎ目に無音・クリック・テンポのずれがない／2周以上（可能なら10分）流し、飽き・疲れを確認／他の曲と音量がそろっている・ピークで歪まない／場面の切り替え（町→戦闘→町、メニュー、ゲームオーバー）でフェードやつなぎが自然・前の曲が残らず2曲が同時に鳴らない／曲と効果音を同時に鳴らし、効果音が聞こえ曲が邪魔をしない／音量スライダー・ミュートが効く・タブを切り替えても破綻しない／一時停止・再開で曲が意図どおり。
**ブラウザ**: 最初の操作（タップなど）の後に音が鳴る（AudioContext は suspended で始まり resume が要る）／複数の AudioContext を作っていない／Chrome・Safari・Firefox で確認。
**スマホ**: iOS Safari は実機で確認（最初に触れるまで無音で始まる）／画面ロック・他アプリへの切り替え・着信からの復帰で、音が戻る、または止まる／内蔵スピーカーで低音が消えても曲として成立する。
**イヤホン／スピーカー**: イヤホンで刺さらない・小さい音量でも聞き取れる／ノートPCの内蔵スピーカーでも成立／音量を大きくしても痛くない。
**アクセシビリティ**: 重要な情報（敵の接近・イベントの合図）を音だけで伝えていない／曲だけ・効果音だけを個別に調整またはミュートできる／点滅や画面の合図と音が対応している。

**音の不具合報告の書式（提案）**
```
種類: ポップ/途切れ/音量差/ループずれ/鳴らない/二重再生
場面と曲名: ◯◯
再現手順: 1... 2...
いつ(秒): 0:42ごろ ／ 何周目か
環境: 機種、OS、ブラウザ、イヤホンかスピーカーか、音量
頻度: 毎回/たまに    期待した動作:
```

## 本プロジェクトへの当てはめ案（Claudeは音を聴けない・人間が聴いて感想をくれる）
1. Claudeが代わりにできるのは**機械的な検査**に限る: 書き出しWAVの両端の無音とゼロ交差／ピークと平均音量の曲間差／曲の長さ（ループが60〜120秒以上か）／同時に鳴る音数／高音域・低音域のエネルギーの偏り（上の変換表と照合）。これらは「計測値」として報告し、聴感の判断とは分ける。
2. 人間への依頼は軽くする: 1回につき曲は1〜3曲、質問はQ1〜Q4とQ10を基本に、無理なら「合う/合わない＋理由一言」だけ。聴く条件（機器・音量）を最初に書いてもらう。
3. 感想は変換表で作業指示に変換し、tracks.md の曲ごとに「聴取メモ」欄（日付・聴き手・機器・感想の原文・変換した指示・対応結果）。原文は書き換えない。同じ指摘が複数人から出たら優先度を上げる。
4. 聴き手は友人・家族など少人数で、偏りを前提に。統計的な結論は出さず、「繰り返し出る指摘だけ直す」。
5. 比較（A版/B版）は、Claudeが音量をそろえた2ファイルを作り、順番を入れ替えた依頼文を2通り用意。聴き手同士で相談しない。
6. 長時間ループ試験: ゲームを放置してループさせ続け、「30分後に疲れたか」だけを聞く。
7. ブラウザ固有の確認は、最初のタップの後に音が鳴るか、iPhone・Android 各1台で確かめる（人間に依頼）。
8. 聴覚の配慮: 設定画面に曲と効果音の別々の音量・ミュート、重要なイベントは文章や画面の合図でも示す。
