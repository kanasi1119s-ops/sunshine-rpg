# プロデューサー役の学習メモ（2026-10-02）
**注意**: 検索結果の要約が中心（本文を読めたページはほぼない）。「一般」「提案」「補」は出典で確かめていない一般的な目安。数値は出発点で、最後は耳（と人間の確認）で決める。既存曲の旋律・曲名は例に使わない（`CLAUDE.md` 1-1）。

## 実務の原則
- **発注書（ブリーフ）に入れる項目**: 作品の説明・曲数・長さ・スタイル・参考曲・使われる場面・予算・期限・ループの有無・テンポ・ジャンル。参考曲は複数あると共通点が伝わる。
- **最初にキューリスト**（音楽が必要な場面の一覧）を作る。目標がはっきりし、曲数がふくらむのを防げる。
- **音楽バイブル（サウンドバイブル）**: 冒頭に3〜5個の「柱」（数語・技術でなく感情で書く）。中心は「スタイルガイド」（和声・リズム・テンポ・音域・長さ）。参考資料には「どこが参考か」の一言を添える。
- **管理表の状態**: 予定→下書き→自己確認済→人間試聴済→承認。
- **フィードバック**: 感情を具体的に（「悲しい」だけでなく喪失か孤独か）。「してほしくないこと」も書く。場所や小節を指す。型は【どこ】【今どう聞こえるか】【どう感じさせたいか】【変えてほしい点／残したい点】。
- **RPG**: 少数のライトモティーフ（人・勢力・理念）を早く決め、編曲を変えて再登場させる（2〜3個でも効果あり）。曲は場所・戦闘・人物・勢力で整理できる。
- **ループ曲**: 終わりと始まりの響きが近く、急な音がない。ループ位置は埋め込むか別紙で渡す。
- **受け入れ基準は発注前に決める**とやり直しが減る（一般）。
- **音量**: 据え置き機は約 -23 LUFS（-25〜-20）、Wwise推奨 -24±2LU、携帯機 -18±2LU、True Peak -2dBTP以下。ブラウザの基準は見つからなかった。

## 曲の企画書（ブリーフ）テンプレ
1. 曲ID・曲名（仮）・使う場面（例: B03 第2章 港町の昼）
2. 役割と感情（「プレイヤーに感じさせたいこと」を1文で）。例「旅の始まりの期待と、ほんの少しの不安」
3. **避けたいこと**（例: 明るすぎて能天気、ホラー調にしない）
4. 音楽の仕様: テンポ・調・拍子・長さ（小節数と秒数）・ループ有無・編成（主役の音色）
5. ライトモティーフ: 使う主題の名前と、どう変えるか
6. 参考にする**性質**（既存曲は使わず、性質を言葉で。曲名は出さない）
7. 前後の曲とのつながり（切り替え方）
8. 納品物: 設計図JSON・MIDI・WAV・登録名
9. 期限・優先度・仮曲か本曲か
10. 受け入れ基準（下）

## 受け入れ基準チェックリスト
- 場面の感情に合っているか（柱と一致）
- 既存曲に似ていないか（1-1。旋律とコード進行を確認）
- ループの継ぎ目でプツッと切れない・長すぎ短すぎない
- 音量が他の曲と大きくずれない・音割れなし・ブラウザ／スピーカー／イヤホンで確認
- 同じ場面で何度聴いても疲れない
- 前後の曲との切り替えが自然（キー・テンポの極端な差がない）
- 曲の長さと容量が予算内（dist/ 128Mbit）
- 一覧表・登録・仮／本の表示が正しい
- 使うライトモチーフが入っている
- **人間が耳で聴いて承認した記録がある**

## フィードバックの文例
- 悪い例:「もっと盛り上げて」「なんか違う」
- 良い例:
  1. 「この場面は『静かな決意』を出したい。今は少し寂しすぎる。弱気な印象は避けたい。」
  2. 「サビに当たる後半8小節で、旋律を1オクターブ上にして伴奏を少し減らすと広がりが出ると思う。」
  3. 「ループの終わりから頭に戻るところで急に盛り上がる。終わりを静かにしてつながりを自然に。」
  4. 「この主題の音は残し、リズムだけ軽くしてください。町の人の穏やかな昼の感じです。」
  5. 「戦闘曲が最初の1分で耳に残りにくい。冒頭の旋律を一度はっきり提示して。」

## 本プロジェクトへの当てはめ案
- 音楽バイブルを docs/sound/ に1つ作る（柱3〜5・スタイルガイド・主題の一覧・避けたいこと・音量の方針。既存曲の名前は書かず性質だけ）。
- tracks.md を場面別の曲一覧（ID・場面・感情・BPM・調・長さ・ループ・主題・状態・仮／本・耳の確認）にする。
- 1項目=1〜2曲で区切り、先に企画書を書く。最初は主題2〜3個と、町・フィールド・戦闘・ボス・タイトルの核になる曲から。ほかは仮曲で埋めて「仮」と表示（1-4）。
- 受け入れは2段階: 第1段=Claudeが自動確認（長さ・ループの継ぎ目・音量の統一・容量・既存曲に似ていないか）、第2段=人間が耳で確認（感情・聴き疲れ）。人間の確認は数曲まとめて依頼し、回数を減らす。
- 人間のフィードバックは上の型で記録し、曲ごとに「版」と「直した点」を残す。やり直しは1曲2回までを目安にし、超えたら仕様を見直す（提案）。
- 参考曲の代わりに、場面の感情語とネガティブ指定（避けたいこと）を使う。
