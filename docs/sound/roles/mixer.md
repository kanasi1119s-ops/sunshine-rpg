# ミキサー（編集）役の学習メモ（2026-10-02）
**注意**: 検索結果の要約が中心（本文を読めたページはほぼない）。「一般」「提案」「補」は出典で確かめていない一般的な目安。数値は出発点で、最後は耳（と人間の確認）で決める。既存曲の旋律・曲名は例に使わない（`CLAUDE.md` 1-1）。

(EQ・コンプ・リバーブ・手順・ダンスのミックス・診断は `docs/sound/mixing-guide.md` に整理済み。ここは、それ以外を調べた分。)

## 原則
- 順番: 準備（極性確認・配置の衝突の整理）→ バランス（**モノラル**でフェーダーとパン）→ 音色 → ダイナミクス → 空間と仕上げ。「**フェーダーが先、プラグインは後**」。埋もれる原因の多くは音量差。
- EQの順は「掃除のEQ → コンプ → 音色のEQ」。濁りを先に除いてから圧縮する。
- **A/Bは音量を揃えてから**。参照曲が1〜2dB大きいだけで「広く明るく迫力がある」と錯覚する。統合ラウドネスは約0.5LU以内に揃える。
- 耳は疲れる（最初に失われるのは奥行き）。45〜50分作業して10〜15分休む。再生環境も変えて見直す。
- **パラレル処理**は「原音を残して足す」手段。パラレルコンプは小さい音を持ち上げつつアタックを保つ。パラレルサチュレーションは主音を歪ませず中域の厚みを足す。
- **サチュレーターとエキサイターは別物**。サチュレーター＝既存の倍音を広い帯域で強め、太さやまとまりを出す。エキサイター＝高域に新しい倍音を足し、空気感を出す。
- 位相は「モノで消える物」を探す。原因になりやすいのは低域・広いステレオ・モジュレーション系エフェクト。
- ゲームのBGMは「ループが主役」。書き出し形式と継ぎ目の処理が品質を左右する。

## 手順とチェックリスト
**ミックスの反復（やりすぎ防止）**
1. 版ごとに保存し、変えた点を1行ずつ記録する。
2. 1回の反復で変える項目は1〜2個。
3. 直す前に「何が問題か」を言葉にする。言えないなら直さない。
4. 処理のON/OFFを音量差ゼロで比べる。良くなっていなければOFF。
5. 休憩を挟み、別の環境で聴いて確認してから完了にする。

**モニター**: クロスフェード（約270〜300μs遅れ・6〜9dB減衰を模す）で過度な広がりを防ぐ／補正ソフトが使えるなら使う／音量は80〜85dB SPL程度／スピーカーかスマホ・ヘッドホン・モノの3系統で最終確認。

**位相・極性**: ①モノにして消える・痩せる楽器を探す ②重なる2音は片方を極性反転し、低域が増える方を採る ③ダブルは数msずらす ④低域はモノにする（Mid/Side EQでサイドの低域を切る）⑤相関メーターを見る。

**ステムによる確認**: ステムを書き出して合計し、全体ミックスと比べる。反転して足せば無音になるはず（ヌルテスト）。残る場合はマスターバスの処理かステムのかかり方の違いが原因。

**ダイナミクス設計**: セクション別の短期ラウドネスを見る。大きな跳びは自動化の不備、平坦すぎれば抑揚の喪失。Mid/Sideの比でステレオ幅を測る（サイドが多すぎるとキック・スネア・声が弱くなる）。

**ゲーム固有**: ループの継ぎ目はリバーブの余韻を先頭に重ねる（DAWの「Wrap Remainder」と同じ考え方）。BGMとSEは役割で音量帯を分ける（Wwise系資料のSEの目安: 最大が-13LUFS、強い音が-18〜-14、主役級が-23〜-18）。動的ミックスでは重要なSEの間だけBGMを下げる（ダッキング）。

## 数値の表
| 項目 | 目安 |
|---|---|
| 相関メーター | +0.5〜+1が目安。-1に近いとモノで消える |
| A/B音量差 | 0.5LU以内 |
| 作業と休憩 | 45〜50分作業、10〜15分休憩 |
| 聴取音量 | 80〜85dB SPL |
| 最大True Peak | -1dBTP以下（非可逆エンコード前） |
| ラウドネス（据え置き機／携帯機） | -24LUFS／-18LUFS（±2LU） |
| 中間ファイルのヘッドルーム | ピーク -6〜-3dBFS |
| ディザ | 16bitの最終書き出しだけ。24bit以上の中間ファイルでは使わない |
| サンプルレート | 制作時のレートのまま |
| ダッキング量（経験則・出典未確認） | BGMを3〜6dB下げる（アタック50〜100ms、リリース300〜800ms） |

## ありがちな失敗と直し方
- EQを先に触る → まずモノでバランスを取り直す。
- 音量差のままA/Bして「良くなった」と錯覚 → 同じ音量にしてから比べる。
- 直し続けて悪化 → 版を戻して比べ、1回に変えるのは1〜2点。
- 広げすぎてモノで消える → 低域はモノにして、メーターで確認。
- **MP3でループに隙間が出る**（遅延とパディングが仕様上記録されず長さがずれる。SafariはOgg Vorbisを再生できない）→ Ogg Vorbis・AAC・Opus・WAVのどれかを使う。長い素材に長いフェードを付ける妥協案もある。
- リバーブがループ点で切れる → 余韻を先頭へ重ねる。
- 16bitに落とすたびにディザを重ねる → 最終の1回だけ。

## 本プロジェクトへの当てはめ案
1. ミックスの優先順位をチェックリスト化: モノでバランス → 極性／相関 → 低域整理 → コンプ → 空間 → 最終確認。診断スクリプトに、PLR/LUFSに加えて相関係数と Mid/Side 比を足す。
2. ループ用書き出しを標準に: 余韻を先頭に足し込んだWAV。ゲーム本体はループ長をサンプル数で持つ形式（WAV、またはOgg＋メタデータ）にし、Web Audioでは AudioBufferSourceNode の loop・loopStart・loopEnd を指定。MP3は使わない。サイズが問題ならOgg Vorbis（必要ならSafari用にAAC）を検証してから採用。（うちのBGMは今は MIDI＋SoundFont のリアルタイム再生なので、ループは MIDI 側のループ点で扱っている。）
3. ディザは最終16bit出力だけ。内部とステムは32bit float。ピークは-1dBTP以下。
4. ステム確認の自動化: パート別に書き出し、合計と全体ミックスの差（ヌルテスト）を残差dBで報告。
5. 動的ミックスのノード構成: BGM→GainNode(BGM)、SE→GainNode(SE)、両方→GainNode(マスター)→DynamicsCompressorNode（軽いグルー）→リミッター→出力。ダッキングは setTargetAtTime でSE再生時にBGMのゲインを下げる。DynamicsCompressorNode はサイドチェイン非対応なので、厳密にやるなら AudioWorklet。**ゲームで聞こえる音とWAV書き出しで測る音を同じ処理にする**（違うと測定が意味を持たない。今回の `--raw` 書き出しはそのため）。
6. BGMとSEの音量帯: BGM -18〜-20LUFS、SEの主役 -14〜-16LUFS（携帯機寄りの仮案。出典のある基準ではない。最終は人間の聴き比べで調整）。
7. サチュレーションは控えめに。ON/OFFを音量差ゼロで比べるのを必須にする。
- 未確認: ディザ方式（TPDF・ノイズシェーピング）の聴感差、OggのLOOPSTART系タグをブラウザが解釈するか、ダッキングの具体的な時定数 → 実測で決める。
