# ボカロ曲アルバム（伴奏の版＋重音テトの歌の版）を完成まで作るプロンプト

2026-10-27 作成。人間「つぎは今回の曲が完成するまでのをまとめたプロンプトを作って」。
アルバム『SCARLET FREQUENCY』（vb25・25曲）を、企画から完成まで作った流れと、途中で人間が言ったことをすべてまとめた。
曲の作り方の土台（型・コード・旋律・音作り）は `docs/sound/vocaloid-inst-prompt.md`。この文書は、その上に「歌の版」「直しの流れ」「仕上げ」を足したもの。
下の「プロンプト」を Claude にそのまま渡せば、同じ流れで作れる。【 】の中だけ書きかえる。

---

## プロンプト（ここから下を渡す）

> ボカロ曲を【25】曲作ってください。1曲ごとに「伴奏だけの版（BGM）」と「重音テトが歌う版」の2つを作ります。
> 合言葉は【楽しく、明るく、自然に】。ジャンルは【テクノポップ・ダンス・ロック・エレクトロニカ・ヒップホップ・J-POP・K-POP】から曲ごとに選んでください。
> 作り方と決まりごとは `docs/sound/vocaloid-inst-prompt.md` と `docs/sound/vocaloid-album-teto-prompt.md` のとおりです。
> 作る前に「曲を決める表」を見せて、承認をもらってから作ってください。点数は最低 7.5、目標 8 です。
> できた曲はチャットで1曲ずつ聞ける mp3 で送り、全部できたら、まとめて全部貼り付けてください。日本語で説明してください。

## 1. 作る前（企画）
1. ジャンルの決まりごとを先に調べる。ボカロの型は `docs/sound/vocaloid-study.md` にある。足りなければ調べて表にする。
2. 「曲を決める表」を作って見せ、承認をもらう。
   - 列: 番号／曲名／ジャンル／テンポの型・テンポ・調／形（物語の言葉での骨組み）／場面と、そこで必要な強さ（山・静けさ）／旋律の性格／派手な展開／重ねる楽器／始まり方 → 終わり方
   - 例: `docs/sound/vp25b-plan.md`
3. 似た曲を作らない。どの2曲を比べても、「形」「場面と強さ」「旋律の性格」の3列のうち、2列以上が違うようにする。続く2曲で、始まり方を同じにしない。その曲の物語でしか出てこない音や展開を、1曲に最低1つ入れる。
4. 曲名はボカロらしく。よく使われる言葉でもよい。ゲームの曲と言われていなければ、ゲームの要素（8bit・ステージなど）は出さない。
5. 1曲に1つ、台本（`assets-src/ai-songs/_gen/vb25_NN_slug.py`）を書く。台本の頭には次のことを書き、部品は `vb25_lib.py` を使う。
   - 物語
   - 場面と強さ
   - 旋律の性格
   - ほかの曲とちがう所

## 2. 歌（重音テト）
- **歌詞**:
  - 直接的な言葉ばかりにしない。少し比喩・隠語・造語で表す。
  - ただし「好きだよ」「ありがとう」のように、そのままがいい所は、場面で使い分ける。
  - 歌詞はひらがなで書き、句ごとに区切る。
- **旋律**:
  - 人間が歌える速さにする。早口すぎない（8分と4分が中心、句の頭を16分で弾ませる程度）。
  - 言葉の途中で息つぎをさせない（句の最後の1音だけ取り残される所を作らない）。
- **声**（`tools/singer/sing.py`）:
  - 人間らしく、少し透き通るアニメ声寄りにする。一字一字が聞こえやすく、ノイズ・濁り・ひずみはなくす。
  - フォルテ・ピアニッシモ・しゃくり・ビブラートを、場面に合わせて使う。
  - 伴奏に対して、声を大きくしすぎない。
- **テンポが途中で変わる曲**: 歌も同じテンポの地図で時間を計算する（`tempo_clock`）。前にここを忘れて、歌が伴奏から数秒ずれた。
- **歌の版の伴奏**:
  - 歌の下のリードは小さく丸くする（2.8kHz を引き、3.8kHz から上を切る）。
  - リードのやまびこ（ディレイ）は外し、歌とぴったり重ねる。
  - 歌が低い小節では、リードを鳴らさない。
  - 歪んだリードで声が聞こえにくくならないようにする（`teto()` が自動でやる）。
- 歌の版で歌詞がはっきり聞こえないときは、次のどちらかで直す。
  - 歌を少し前に出す（例: 0.6 → 0.68）
  - 子音を強くする

## 3. 伴奏で、人間が言ったこと
- **ドラム**:
  - その曲に合ったものにする。全曲を一律に変えない。学んだプログレのフレーズ（GMD）を、ふつうの曲に広く入れない（「ぐじゃぐじゃに聞こえる」）。
  - シンプルなフレーズを、曲ごとに選んで入れる（`S.dmoves`）。
  - 刻みの楽器は、場面ごとに持ちかえる（`S.keepers`: ライド・カップ・クラッシュの4分・開いたハイハット・フロアタムなど）。エイトビートでも、ハイハット以外で刻む場面を作る（「これ重要」）。
  - ハイハットの開け閉めを使い分ける。開いた音は繊細に（`S.open_hat_vol`）。
  - フィルは、ただ回すのではなく、アクセントになるもの（キックと合わせる・間を空ける）にする。続けて同じフィルにしない。
  - 「普通のエイトビートでいい」と言われた場面は、遊びを入れない（`S.plain_scenes`）。ただし、そのぶん伴奏がさみしくならないように、ピアノやベースを足す。
  - 音は、素直な生ドラム（Naked Drums・`S.kit = "naked-x"`）が「デジタルすぎない」。点数も上がった。
- **ギター**:
  - 丸みのある音にする。6kHz から上をなだらかに落とし、高い所の持ち上げはしない（「ちょっと音が強い」）。`vb25_lib.vwrite` が自動でやる。
  - 大きすぎてほかの音を消さないようにする。
  - リフギターが目立つ曲は、ベースを 1.2 倍にして、ギターの低い所を削る。
- **ベース**: シンセのベースより、生のベース（`S.live_bass`、`--bass bnb`）のほうが点数が上がった。
- **ピアノ**:
  - 単音ばかりにせず、和音・左手と右手で弾くイメージにする。
  - 前に出してほしいと言われたら、大きさと 3kHz あたりを上げる。
- **大きさの段差**: 曲の途中で不自然に小さくならないようにする（特に前奏 → Aメロ）。仕上げで `vb25_fixlevel.py` を使う。
- **音色**: 気に入った音でも、全曲に同じ音を入れない。リードなどは、曲調に合わせて曲ごとに選ぶ（`S.patch_swap`）。
- **効果音**（例: 02 の花火）:
  - 録音素材を自動で取ってこない。合成で作る。
  - 本物らしさは「高さのない衝撃波＋距離で高い音が削れる＋屋外の不規則なこだま」で作る（`tools/mv/fireworks_sfx.py`）。
  - 曲には、仕上がった音に重ねて入れる（`tools/mv/mix_fireworks.py`）。
  - 効果音は点数を少し下げる。下がっても 7.5 を越えていればよい。

## 4. 書き出しと確認（1曲・1版ごと）
- 台本 → JSON。
  - 伴奏の版: `python3 vb25_NN_slug.py /mnt/user-data/outputs/vbq/vb25-NN-slug-vX.json`
  - 歌の版: `VB_VOCAL=1` をつけて `...vXvo.json`
- 書き出し:
  - 雲の待ち行列（`tools/vb25-pipeline/cloud_queue2.sh`・同時に2本まで）か、パソコンの書き出し係を使う。
  - `vb_render.sh` → `vb_finish.sh` で、次のところまで自動でやる。
    - 低い所の掃除
    - フェード
    - 前奏の大きさ
    - 点数（Audiobox の PQ）
    - mp3
  - 名前つきの mp3 には、高い所の仕上げとリミッター（伴奏 0.89・歌 0.89）が入る。
- 確かめること（送る前に、全部）:
  - 点数: 伴奏の版・歌の版とも 7.5 以上（目標 8）。点数だけで判断しない。
  - 品質の自動チェック（`vb25_qc.py`）で見る所:
    - 歌が混ざっているか
    - 言葉の途中の息つぎ
    - 前奏とAメロの段差
    - 場面ごとの段差
    - こもり
    - 単調な場面
  - 雑音（`tools/audio-check/noise-check.py`）: 音割れ・直流・超低域・プチッ。プチッは `declick.py`、取れないものは前後の波形から予測して埋める。
  - 歌の音程: 歌の版を音程で測り、ずれ（中央値で数セント）を見る。
- 直したら版の番号を上げる（vX → vX+1）。前の版は消さずに比べられるようにする。

## 5. 送り方・完成のしかた
- mp3 は zip にせず、チャットで1曲ずつ聞ける形で送る。名前は次の形。
  - 「NN 曲名（BGM・仮）vX.mp3」
  - 「NN 曲名（歌：重音テト・仮）vX.mp3」
- 人間が「全部完成するまで待つ」と言ったら、途中は送らず、最後に**全曲をまとめて貼り付ける**。抜けがないか、曲番号を数えてから送る（前に 01・03・25 を貼り忘れた）。
- 人間が「この版で決定」と言った曲の扱い:
  - `docs/sound/vp25b-plan.md` の「完成した曲」の表に、版・日付・置き場所を書く。
  - Google ドライブ「【ボカロ曲25曲（重音テト）】」に、「NN 曲名（BGM）.mp3」「NN 曲名（歌：重音テト）.mp3」の名前で置く。
- 未完成の曲は「仮」と書く（CLAUDE.md 1-4）。

## 6. 作業のしかた（つまずいた所）
- 雲の CPU は2つ、空き容量は約2GB。
  - 作曲ソフトの書き出し（node）と動画の書き出しを同時に動かすと遅くなり、1時間の時間切れで落ちることがある。落ちたら待ち行列に戻す。
  - いらない wav はこまめに消す。
- `pkill -f` / `pgrep -f` に自分のコマンドの文字を含めると、自分のシェルが止まる。`ps -eo pid,args | awk` で、引数をきっちり比べる。
- 同じ書き出しを2本同時に動かさない。始める前に `ps` で確かめる。
- 実行中のシェルスクリプトは書きかえない。
- ffmpeg を `while read` の中で使うときは、`-nostdin` か `< /dev/null` をつける。
- 曲の音を2つの版で変えるときは、台本の後ろのほうに音量の上書きがないかも探す（前に、上書きが残っていて直しが効かなかった）。
