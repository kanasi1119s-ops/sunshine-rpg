# 旭さんの曲づくりの好みと決まり（作曲ソフトで曲を作るとき、毎回はじめに読む）

クラウドの Claude が会話の中で教わってきたことを、パソコンの Claude Code でも同じように守れるようにまとめた（2026-10-29）。新しく教わったら、ここに書き足す。

## 進め方
- 話し・報告・説明・コミットは日本語。子どもからお年寄りまで読めるやさしい言葉で。
- 作るときは情報を深く集めてこだわる。学ぶ・調べるよう頼まれたら、早く切り上げず徹底的に。ジャンルの決まりごと（見本）を先に確かめ、無ければ調べてから作る（全部なぞる必要はない）。
- 作る前に「曲を決める表」を書いて見せる。列: 曲／形（物語の言葉での骨組み）／場面と、そこで必要な強さ／旋律の性格（＋始まり方・終わり方・山・伴奏の主役・ただひとつ）。ほかの曲と並べて、始まり方と終わり方・山と静けさの置き方・旋律の動き方とリズムの形・リードとリフの音が似ていないか確かめ、似ていたら作る前に直す。
- 曲にはストーリーを持たせる。その曲の物語でしか出てこない音や展開を1曲に最低1つ入れる（ただひとつ）。
- できた曲は zip にまとめず、mp3 を1曲ずつ、その場で聞ける形で渡す。保存先: C:\Users\fujik\Downloads\<曲集の名前>\ と G:\マイドライブ\<曲集の名前>\。
- 点数は基準として必要だが、最後は耳で判断する。書き出したら点数だけで判断せず、区間ごとに単調なところ・急に小さくなる所・前奏が小さすぎる所がないか確かめてから渡す。
- 音質の点数（Audiobox Aesthetics の PQ）: ふだんの曲は最低 7.5、目標 8。ケルト100曲は 静の曲 7.0・動の曲 7.5 を超えればよい（2026-10-29 に 7.2・7.8 から変更。「似たような感じからはなるべくしないで」）。
- 音量を「5上げて」「10下げよう」と数字で言うときは割合（5上げ＝×1.05、10下げ＝×0.9）。調整は 1〜10 ではなく 1〜1000 くらいの細かさで。パート別に数値で調整してから、最後に全体を調整する。
- ゲームの曲と言われたときだけゲームの曲（曲名や音にゲームの要素を出さない）。曲名はよく使われる言葉でもよい。
- **点数を上げるために、全部の曲に同じ処理を入れない**（2026-10-29「点数あげる為に全部同じにしない。それはただの作業でしかない」「楽するな。１曲を丁寧に作り上げなさい」）。床・きらめき・厚い弦・前奏の持ち上げなどの部品は、その曲の場面に要るときだけ、その曲に合う形で使う。似た所があってもよいが、始まり方・弾き方・流れが全部同じになるのはだめ。全曲に関わる変更は、勝手にせず先に相談する。
- 一度決めたことを全曲に当てはめない。固定概念に頼らず柔軟に。追加した音源は「使える素材」で、毎回使う決まりではない。省きすぎて薄くしない・ごちゃごちゃして聞きにくくもしない。

## 曲づくり全般
- 同じような曲・似た曲・つまらない曲・単調な曲・曲として成り立っていない物は作らない。展開の骨組み・旋律・リズムの形が似た曲はいらない。既存の物にとらわれない旋律に。
- 全曲を同じ展開にしない。始まり方（サビから・前奏・ドラムだけ・ベースだけ等）・流れ・終わり方を曲ごと・物語ごとに変える（ただし「必ず変える」も固定概念。同じリフのままでもよい）。
- 強弱は区間の種類で決めず、場面ごとに必要な強さを決める。人が演奏しているように。全曲に人間っぽさ。
- 曲の途中で不自然に音が小さくならない（特に前奏→Aメロ）。前奏が小さすぎないか作るときに確かめる。
- 音域（スケール）を広く使う。定番のコード進行以外もやる。
- リードなどの音色は曲調に合わせて曲ごとに選ぶ（気に入った音でも全曲に同じ音を入れない）。曲ごとに1つだけ入れる楽器は主役として音量を上げてよい。
- FX はいくつか作って重ねて、空間の透明感と深みを出す。場面のある曲はその場面の空気（環境音）も感じられるように。ただし「空間を支配する」は、作った効果音や環境音で埋めることではなく、**音楽の音そのもので耳を気持ちよくして支配する**こと（2026-10-29）。
- ピアノは単音ばかりにせず、コード弾きも入れて左手と右手で弾くイメージに。主旋律と速弾きで別トラックに分けてもよい。
- 場合によって: ベースを2種類重ねる／ドラムに場所ごとのインパクト音／キックを2種類／わざとノイズ音を入れて深み／シンセでデジタルっぽく空間を支配する。

## ドラム
- 単調にしない。緩急・間・グルーブ。強弱・アクセント・ゴースト。ライド・タム・フロアも使う。シンバルは鳴りを伸ばす（すぐ止めない）。
- その曲に合ったドラム。エイトビートでもライドで刻むなど、ハイハット以外も曲に合わせて。オープンとクローズのハイハットの使い分け。
- 学んだプログレのテクニックをふつうの曲に一律に当てはめない（ぐじゃぐじゃに聞こえる）。シンプルなフレーズを色々、曲に合うものを。フィルはただ回すだけでなく、アクセントになるカッコいいフィル。
- 音色: Naked Drums の素直な版（処理なし）が好評。ジャズも Naked Drums。

## ギター
- 使わない音: 短い単音の刻みで「ピ、ピ」と切れる高いギター／歪みすぎて割れる・高域がピーと鳴る歪み／chorus をかけたクリーン（きゅいんきゅいん）／リードの標準 crunch アンプ（ピロピロ）。詳しくは banned-sounds.md。
- ブリッジミュートの刻みをなんでも入れない（特に曲の最初が刻みだと聞きにくい）。弾いている途中で急にミュートに切りかえない。
- ビブラートは「ゴムが伸びる音」に聞こえるので嫌い。チョーキングはよいが、戻しが速く「上がって落ちる」のはだめ。
- 歪みは明るい歪み。リフは歪ませつつ「ラウドな透明感」。リードの高音は少しだけ低めにし、余韻を残して「鋭いけど優しく心に響く」。ゲームっぽくない現代的な音。
- プロのエフェクター接続・複数のエフェクターの組み合わせを取り入れる。エフェクトはつまみで細かく調整できるように。
- ギターは「Rギター・Lギター・リードギター」の三種で作れるように。アコギは柔らかめ。ギターが大きすぎてほかが聞こえない曲にしない。

## ベース
- ふつうはコード進行の根音に沿わせてよい。メロディラインのあるベースは丁寧に。
- ラウド: 歪ませてよいが、こもった音ではなく明るくゴリッと。指弾き。ベースは少し大きめが好み（×1.2）。
- ジャズ: 全部ウッドベース、指で弾く感じ、一音一音はっきり。

## ジャンル別
- ラウドロック: BMTH 寄りの音（参考の音 wide-dark-wall）が好評。バスドラはトリガー＋重みのあるバスドラ。
- バンドの音: TRiDENT の音（参考の音 glossy-jrock・ドラム crocell-punch）。曲に合わなければ使わなくてよい。
- ジャズ: 電子音は使わず録音の原音、ジャズでふつう使う楽器だけ。硬さを抜いて柔らかく全身を包む音色、居心地のよい空間、頭の中を支配する音、一音一音丁寧に。ギターは繊細に。ライドは伸びて鋭く。一流の奏者の技術・ミキシング・音作りを楽器ごとに学んでから。
- バイオリン（フィドル）: 柔らかく力強く、透き通るように。
- ケルト: 音全体に強弱と余韻、スケールの大きさと幻想的な感じ、「頭の中を全て支配するような感じ」。1曲ごとにその曲のイメージ（場面・物語・ただひとつ）を大事にして、形・拍子・楽器・始まり方・終わり方を選ぶ。
- ケルト・フルート: 主役のフルートを伴奏やシンセより小さくしない。高音は硬くせず柔らかく、滑らかで優しい吹き方。オーボエなど笛以外の旋律楽器は並べない。終わり際のクラッシュシンバル系はいらない。環境音だけが鳴る時間を作らない。詳しくは celtic-flute-100-plan.md・celtic-flute-100-ledger.md・celtic-study/。
- 自然を感じる曲は、その空間が感じられる音に。

## 歌（テト）
- 人間らしく、少し透き通る、少しアニメ声寄り、一字一字聞こえやすく。ノイズ・濁り・ひずみなし。フォルテ・ピアニッシモ・しゃくり・ビブラートを場面で。伴奏に対して大きくしすぎない。人間が歌える速さに。
- リードの歪みが強いと声が聞きにくい → リードの歪みは抑えめ。
- 歌詞は直接的な言葉ばかりにせず、比喩・隠語・造語も。「好きだよ」「ありがとう」などは場面でそのままと言いかえを使い分ける。

## 仕上げ
- 書き出しの標準: 音量を下げて左右の広げなし（-13.5 LUFS・widen 1.0）の「B」でよい（曲集ごとに決めた値があればそれ）。
- 2026-10-29 旭さん「物語考えたら主役笛じゃない？」: 銀の笛と百の夜の主役は、どの曲もエイラの笛。伴奏（ピアノ・竪琴など）が旋律を持つ曲でも、伴奏は奥、笛が前。山と最後は笛が持つ。

## 2026-11-01 何回直しても点数が変わらない曲
- 旭さん「何回もやっても変わらないなら完成でいいよ」。直しても点数が動かない曲は、目安（静 7.0・動 7.5）に届かなくても完成にしてよい（012 7.41・004 6.79 をこれで完成）。点数のための同じ処理のくり返しはしない。

## 絶対条件: 似た曲を作らない（2026-11-12 人間「絶対条件でここで作った曲で似た曲を作らない。過去の物も含めて。1曲1曲こだわって作る」）

- これまでに作った全部の曲（この第3弾だけでなく、過去のアルバムも）と、旋律・ベース・展開・音の選び方が似た曲を作らない。
- 2026-11-12 に数えたら、vt3 の 02（v3）は、旋律のリズムが 03 と 88%・過去の vb25-01 と 86% 同じ、ベースの型が過去の曲と 79% 同じだった。
  原因は、旋律を「半拍休み → 8分で上がる → 長い音 → 休み」の型で書き、ベースを共通の部品（`bass_line` の root8・oct8・walk・long）で書いていたこと。
- 決まり:
  1. 旋律とベースは、共通の部品や前の曲の型を使わず、その曲の物語と曲調のために書く（`bass_line` は使わない）。
  2. 書いたら、書き出す前に `python3 tools/vt3/similar_check.py <歌入りの JSON>` で、これまでの全部の曲とくらべる。
     目安: 旋律の動き 25% 未満・旋律のリズム 60% 未満・ベースの型 50% 未満。こえたら書き直す。
  3. 音の種類・音域・奥行き・場面ごとの強弱・その曲だけの仕掛けも、曲ごとに決める。同じ手順を何曲にも当てはめない（「2曲目から手抜き感しかない」と言われた）。
  4. 同じサビを同じ編成で3回くり返さない。場面ごとに足す音・引く音を変えて、単調にしない。
  5. 数字は入口。最後は耳で確かめてもらう。

### 作る順番（2026-11-12 人間「必ず次の曲作る時、1回曲調が以前のものと似てないか確認してから作るようにして。あとプロみたいにこだわって作って」）

1. **書く前**に、決めた曲調（テンポ・和音の進み方・使う音色）を、今までの全部の曲とくらべる:
   `python3 tools/vt3/similar_check.py --plan bpm=122 chords="Ebmaj9 Dbmaj9 Cm9 Abm6 ..." patches=kfbGlassEp,kfbSub,...`
   目安（近さ 50% 未満・音色の重なり 60% 未満・和音の進み方 60% 未満）をこえたら、曲調を決め直してから書く。
2. 書いたら、歌入りの JSON で `python3 tools/vt3/similar_check.py <JSON>`（旋律・ベース・曲調の全部をくらべる）。こえたら書き直す。
3. 直前の曲と、テンポ・ノリ（4つ打ち／2ステップ／ハーフ／シャッフル…）・主役の音・始まり方・終わり方のどれも同じにしない。
4. 既にある曲に音を足して直すのではなく、つまらないと言われたら曲そのもの（テンポ・和音・節・音の世界・展開）から決め直す（02 は v4 まで足すだけで「クソつまらない」「プロが作る曲ではない」と言われ、v5 でゼロから作り直した）。

### 違う感じがしたら、その都度ネットで作り方を学ぶ（2026-11-12 人間「違う感じがしたらプロになれるように、ネットで作り方をその都度学んできて」）

- 曲調を決めたら、書く前にそのジャンルの作り方（テンポの幅・ドラムの置き方・はね方・ベース・和音・展開・ミックス）を調べ、台本の中に「調べた決まり」と出どころを書く。
- 「つまらない」「素人っぽい」「違う」と言われたときも、当て推量で直さず、まずプロの作り方を調べてから直す。
- 例（02 v5）: 2ステップは、テンポ 125〜138・キックは1拍目と3拍目の裏・クラップは2と4・ハイハットは裏拍で16分をはねさせる（キックはまっすぐ）・ベースはキックのあいた所に答える。
  はじめ 122・はねなしで書いていたのを、調べてから 128・ハイハットだけはねる形に直した。

### 効果音と息の音（2026-11-12 人間。02 v5 を聞いて）

- 声の「吐息みたいなノイズ」はいらない → 句の合間の息つぎの音（breaths）は入れない。ウィスパーの声は息の成分を減らして使う（breathy 0.12・air 3.5）。
- 効果音は、曲に合っていない入れ方をしない。調にもテンポにも関係なく鳴る1発もの（上がる音・インパクト・きらきら・サブドロップ・電子のハットの連打）を、決まりのようにサビの頭や終わりに置かない。
- 入れるなら曲に合わせる: 和音の音・テンポに合った長さ・その曲の物語にある音（02 の電波の「じー」はよい）。場面のつなぎは、まず楽器の音（フィル・シンバルのふくらみ・和音の駆け上がり）で作る。

### 03 v4 を聞いて（2026-11-12 人間）

- 「1 残らない」→ サビの節は、同じリズム・同じ形を、すぐ続けてくり返す（1回のサビで何度も出す）。毎句ちがう節にしない。曲の頭と終わりで楽器も同じ節を弾く。
- 「2 気持ちよさが欲しい」→ ゆれる拍子（8分の6 など）では、8分の流れを止めない（サビで分散和音を和音打ちに変えない）。ドラムは小節ごとに型を変えず、同じゆれを保つ。
- 「3 少しうるさい」→ のこぎり波の和音は小さく・丸く・のばして使う。すき間をあけて刻むと耳につく。
- 「4 外して」→ 物語の音でも、1発ものの効果音（紙コップのコトン）は入れない。
- 「5 ある」→ ウィスパーの声（弱音源 75%）は、息の設定を下げても息の音が残る。伴奏が薄い場面では使わない（クリアの声を小さく歌わせる）。
- 「6 やや単調」→ 間奏は、主役の線のほかに、下で動く線（チェロ）や、後半で重なる音を入れて、前半と後半を変える。
- 「ベースラインを少し丸くして。中に収める様な感じ」→ バラードの指弾きのベースは、弦をはじく高い成分（1k・2.2k）を持ち上げず、900Hz から上を丸める。オクターブへ跳ばず、根音と5度のあいだで、切らずにつなぐ。

### 歌の「吐息のノイズ」（2026-11-12 人間。03 v5 を聞いて「吐息のノイズあるね」「あかりって歌詞のとこで全部ノイズ入ってる」「似たようなの他にもないかチェックして」）

- 正体: 息つぎの音でもウィスパーの声でもなく、**子音と、母音から子音へ移る所の、音程のない息の音**（は行・さ行・か行・た行。「あかり ひとつ」の「り」の中と「ひ」「つ」「ち」）。
  音源そのものに入っていて、子音の強さ（consonant）や弱音源のまぜ方（blend）、高い所の持ち上げ（eq・air）を変えても小さくならなかった。
- 直し方: `tools/singer/sing.py` の `debreath`（音程のない所だけ小さくする。母音はそのまま）。vocals の全部（主旋律・ハモリ・チョップ）に `"debreath": 1.6`。
- **送る前に必ず** `python3 tools/vt3/breath_check.py <歌入りの JSON>` で、歌の最初から最後まで調べる。目安: 母音との差 −6dB より大きい所が 0 か所。
- 伴奏が薄い場面（ピアノだけの Aメロ など）ほど目立つ。静かな曲ほど念入りに。
- 息つぎの音（breaths）は入れない。ウィスパーの声は、伴奏が薄い場面では使わない。

### 歌が入ったとたんに音量が下がる（2026-11-12 人間「歌詞入るとたんに不自然な音量下げやめよう。違和感しかない」「最初からノイズないか必ずチェックしな」）

- 原因（03 v5・v6）: 出だしの場面だけを仕上げ（final_gain）で +10〜+16dB 持ち上げ、次の Aメロ はほとんど持ち上げなかったので、歌が入る所で伴奏が 12〜15dB 下がった。
- 決まり:
  1. 前奏・冒頭が小さいときに、その場面だけを仕上げで持ち上げない。伴奏そのもの（パートの音量・scene_gain）を大きくし、次の場面と同じ値でつなぐ。
  2. 歌が入る場面の変わり目は、BGM の「前2秒 → 後2秒」の大きさを測り、下がっていない（差 2dB まで）ことを確かめる。
  3. 静かにしたい場面（ブリッジなど）でも、歌が入る瞬間に伴奏を 6dB より大きく落とさない。
- 送る前のチェック（毎曲・最初から最後まで。数だけでなく、どこの何の音かまで見る）:
  - `python3 tools/vt3/breath_check.py <歌入りの JSON>`（歌の息の音）
  - `python3 tools/audio-check/noise_scan.py <書き出した音> --bpm <テンポ>`（出た所を1つずつ、声か伴奏か・何の音かまで確かめる。ハイハットや縁の音は誤検出、終わりの響きの消えぎわも雑音ではない）
  - 場面の変わり目の前後2秒の大きさ

### 歌の「吐息のノイズ」がなぜ出るか（2026-11-13 調べた。人間「とりあえずなんでノイズが出るの調べて」）

03 v5 の声（debreath をかける前）で、声を作る段階ごとに「声なし（音程なし）の所が、母音にくらべてどれだけ大きいか」を測った。
道具: `tools/vt3/noise-trace/pieces.py`（1音ずつ、もとの録音とくらべる）・`stages.py`（段階ごとの大きさ）。

| 段階 | 母音との差（中央） | 母音と 6dB 以内の大きい所 |
|---|---|---|
| もとの録音（テトの音源）の子音 | −18dB 前後 | — |
| 声を作った直後 | −12.4dB | 4 か所 |
| 1音ごとに音量をそろえた後 | −10.4dB | 9〜10 か所 |
| 基本の EQ の後 | −11.3dB | 10 か所 |
| **「クリア」の声の EQ（2kHz +9dB・6.5kHz から上 +10dB）の後** | **−7.7dB** | **23 か所** |
| シー取り・コンプの後 | −7.7dB | 23 か所 |

原因は3つ。どれも音源ではなく、こちらの作り方:
1. **声の作り方の誤り**（`sing.py` render_piece の「有声・無声の見直し」）: か・さ・た・は・ぱ行の音で、かすれの多いコマを「声なし」に直す処理が、
   子音だけでなく**前の母音の部分**にもかかっていた。「い」「う」は 1〜4kHz のかすれの値が高く出るので、「い→ひ」（あかり**ひ**とつ・ろうかに**ひ**びくよ）では、
   もとの録音ではきれいに声が出ている「い」を 100ms「声なし」にし、うち 45ms が**母音と同じ大きさのささやき**になっていた（0:19 の「り」の中・0:38 の「に」の中）。
   見直しを子音のあたりだけに限ると消える（実験: 大きいもの 2 → 0 か所）。
2. **1音ごとの音量そろえ**で、子音が 2dB ほど持ち上がる。
3. **明るくする EQ**（透き通った声にするための 2kHz +9dB・6.5kHz +10dB）が、母音より子音・息の音を 3.6dB 多く持ち上げる（大きい所 10 → 23 か所）。
   息の音は高い所の成分が多いので、高い所を持ち上げる EQ をかけると、声より先に息が大きくなる。

息つぎの音・ウィスパーの声・弱音源のまぜ方は、主な原因ではなかった（やめても消えなかったのはそのため）。
debreath（音程のない所を一律に小さくする）は結果だけを押さえる対症療法で、子音までけずって声が変わる。原因のほう（1 と 3）を直すのが先。

### 歌声で「今後必ずやらないこと」（2026-11-13 人間「ではこれを今後必ずやらない事にしましょう」）

歌声の仕組み（`tools/singer/sing.py`）に、次の3つを入れない。直した内容はすでに仕組みに入っている。

1. **前の母音を「声なし」に書きかえない。** 無声子音（か・さ・た・は行など）の手前の母音は、声のまま残す（書きかえは子音の部分だけ）。
2. **音量そろえで、息・子音を持ち上げない。** 小さい音を持ち上げるのは、音程のある所（声）だけ。
3. **明るくする EQ を、息・子音にかけない。** 高い所を持ち上げる EQ・「空気」は、声の所だけにかける。

- たしかめた結果（03 の主旋律）: 母音との差が −6dB より大きい息の音 21 か所 → 8 か所（3つを直しただけ）→ 1 か所（debreath 0.5 を足したとき。残りは「く」の出だしの 0.04 秒）。
- debreath は強くしない（上限 0.5）。1.6 にすると子音まで消えて、声が変わって聞こえる（人間「声変わってない？」）。
- 新しい声の設定・EQ を足すときは、必ず `breath_check.py` で足す前と後をくらべる。

### 歌入りの版は、伴奏を 0.9 倍にする（2026-11-13 人間「声以外のバック音量0.9ぐらいにしようか」）

- 歌入りの版では、声以外（伴奏・ドラム全部）の音量を 0.9 倍にする。曲の台本の仕上げで `backing(path, 0.9)`（`vt3x_lib.py`）を呼ぶ。BGM の版は変えない。
- 息の子音が多い歌詞（「ち」「し」が続く速い曲）は、`softCons`（息の子音だけ小さくする。0.5 で約 −6dB）を使う。debreath は 0.5 まで。
- 伴奏の裏拍のオープンハイハットは使わない（04 で、オープンにした場面だけ採点が 6.1〜6.5 に落ちた。08 でも同じだった）。
