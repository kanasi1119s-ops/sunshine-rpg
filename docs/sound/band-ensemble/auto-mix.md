# 自動ミックス（パートごとに数字で測って、最後にまとめて調整する）（2026-10-14）

人間（旭さん）の依頼: 「音を数値化して確認しているが、各パートごとに音を数値化して調整して、最後にまとめて調整して。毎回、音のぐじゃぐじゃ感が多い」。

**この道具は耳では確かめていません。** すべて波形から測った数字と、docs/sound の目標値の比較です。目標値の多くは【推】（出発点）なので、最後は人間の耳で決めてください。

普通の書き出し（`song.mjs build`）の出力は変えていません。自動ミックスは別のコマンドです。

## 1. 使い方

```
node tools/composer/song.mjs automix <曲.json> [--out <フォルダ>] [--loop [N]] [--apply [<出力.json>]] [--apply-in-place]
     [--bass pick --drums rock --guitar gretsch --piano salamander --orchestra vsco --soundfont gu --edition real --sound <セット>]
     [--master-preset rock-clean] [--family rock|punk|jazz|game] [--lead <パート番号>] [--roles "6=cymbal,12=counter"]
     [--window 0.25] [--no-split-drums] [--json] [--html <作曲ソフトHTMLの置き場>] [--keep-wav]
```

- 音源の指定（`--bass pick --drums rock --guitar gretsch --piano salamander`）と `--master-preset` は、`build` と同じものを渡す（同じ音で測るため）。
- 何もしないと **測定とレポートだけ**。元の曲は書き換えず、`<out>/<曲名>.automix.json`（提案版）と `<曲名>-automix.md`（日本語のレポート）、`-automix-metrics.json`（数字）を出す。
- `--apply` は反映版を `<曲と同じ場所>/<曲名>.automix.json`（または指定したパス）に書く。`--apply-in-place` は元を `<曲名>.json.bak-automix` に残して上書きする。
- `--loop N`（既定 3、最大 6）: 調整を反映 → 描き直し → 再測定を、調整案がなくなるまで繰り返す。**1 回の測定が約 3 分**（全体 1 回＋ドラムの種類ごとに 1 回ずつ）。ブラウザは 6 回の描き出しごとに開き直す（メモリが増えて止まるため）。
- 役割の自動判定が外れたら `--roles "番号=役割"` か、曲の JSON のパートに `mixRole` を書く（`mixRole` を曲の読み込みが受け付けるかは未確認なので、まず `--roles` を使う）。役割名は `src/audio/auto-mix-targets.ts` の `ROLE_SPECS`。
- 作曲ソフトの HTML（約 157MB）は自分用のコピーを `--html`（既定は OS の一時フォルダ）に作る。共有の `dist-composer` は使わない。

## 2. 何を測るか

| 段階 | 内容 |
|---|---|
| ① パートごと | 統合 LUFS（BS.1770 の K 特性・ゲート付き）、ショートターム（3 秒）最大、サンプルピーク、クレスト、7 帯域（Sub 20-60／Bass 60-120／Low-mid 120-250／Mud 250-500／Mid 500-2k／Presence 2-5k／Air 5k+）、スペクトル重心、ステレオ（左右の相関・Side−Mid の幅・左右バランス・150Hz 以下の相関）、鳴っている割合 |
| ② 役割の目標との比較 | 鳴っている間の力（左右の平均 RMS）を、リード = 0dB として目標と比べる |
| ③ パート間のマスキング | 時間窓（既定 0.25 秒）ごとに、帯域ごとの「主な担い手（その帯域の最大から 6dB 以内）」の数、200-500Hz の濁り、キックとベースの低域の重なり、リードの聞こえやすさ、同じ帯域で同時に強いパートの組み合わせ |
| ④ 調整案 | volume／gainDb・pan・duck・既存の fx（filter の highpass、eq）。新しい処理は足していない |
| ⑤ 全体 | master-preset 適用後の LUFS・トゥルーピーク・PLR・クレスト・4 帯域（mix-targets.json）・1/3 オクターブ幅の傾き・ステレオ幅・相関・左右バランスと、preset／EQ の案 |

**ぐじゃぐじゃ指数（0〜100、小さいほどすっきり）** = 濁り度・中域の混み・キックとベースの重なり・リードの埋もれの平均。0〜25 すっきり／25〜50 やや混む／50 以上 混んでいる。**このツールで決めた目安で、耳での感じ方と照らして校正していません。**

### 測り方の要点（実装は `src/audio/auto-mix.ts`、`tools/composer/entry.ts` の `renderStems`）
- 1 回の描き出しで全パートを取り出す。MIDI チャンネルごとに別の出口を作り（`Track.stemKey` で、同じチャンネルになるパートを分ける）、OfflineAudioContext のチャンネルを 2+2n 本にして一度に録る。最大 15 本。
- ドラムは 1 チャンネルを共有するので、太鼓の種類（キック・スネア・ハイハット・タム・シンバル）ごとにドラムだけを描き直して分ける（`--no-split-drums` で省く）。大きさの尺度は全体の描き出しと同じ（`fixedGainDb`）。
- 測る場所は **アンプ・エフェクターのあと、全体の EQ／圧縮／ホール残響の前**。全体の尺度は `renderWav` と同じ -16 LUFS にそろえる。MIDI の reverb の送りは含まれない。
- FFT は 4096 点・ハン窓、左右を 1 つの複素 FFT にまとめて計算。

## 3. 目標値の表（`src/audio/auto-mix-targets.ts`）

### 3.3 全体（`MASTER_FAMILIES`）
ロック／ポップ: LUFS −11〜−9、PLR 9〜14.5、左右の相関 0.4〜0.88、preset `rock-clean`（つぶれ気味なら `rock-open`）。パンク／メタル、ジャズ、ゲームも同じファイルにある。帯域の目標は `docs/sound/data/mix-targets.json`、傾き −1.5dB/oct ±1【推】、クレスト 10dB 以上（punk-guide.md §8）。

## 4. 調整のしくみ

| 手段 | 使い方 |
|---|---|
| 大きさ | ドラムと、他のパートと同じチャンネルを共有するパートは `volume`（SoundFont の 2 乗則で `10^(dB/40)` 倍。実測で合わないときは `MIX_RULES.volumeDbPerDecade`）。それ以外は `gainDb`（アンプのあとの純粋な増減で、音色が変わらない）。 |
| 1 回の反復の動き | 差が 2dB 未満なら動かさない。差の 0.8 倍を、最大 6dB まで。 |
| EQ | 既存の fx の `filter`（highpass）と `eq` を使う。削りは合計 −3dB まで（mixing-guide.md）。`automix` の印を付け、次の反復で置きかえる（積み上がらない）。 |
| キックとベース | 低域で差 4dB 以内の窓が 40% 以上なら、ベースに `duck`（`recommendDuck`）。 |
| pan | キック・ベース・リードが中央から離れていれば 0 に戻す案、同じ役割のリズムギターが 2 本以上で中央に寄っていれば左右に広げる案。 |
| 直せないもの | ドラムの低域カット、音域の重なり（編曲）は「書き込めない提案・注意」として文章で出す。 |
| 無音のパート | 描き出しで無音だったパートは測定・調整から外し、警告を出す。 |

## 5. summer-rock3 での結果（2026-10-14、`--loop`、耳では未確認）

条件: `--bass pick --drums rock --guitar gretsch --piano salamander --master-preset rock-clean`。

| 指標 | 調整前 | 調整後（3 回反映） |
|---|---|---|
| ぐじゃぐじゃ指数 | 42（やや混む） | 9（すっきり） |
| 濁り度／中域の混み % | 22／53 | 13／6.4 |
| キック×ベースの重なり % | 9.4 | 18.2（悪化。目安 40% 未満には収まる） |
| リードの埋もれ | 82 | 0 |
| 目標から外れたパート | 10 | 4（ドラムが最大 6dB × 3 回では足りず残った） |
| LUFS／TP／PLR | -10.1／-1.2／8.9 | -10.2／-1.3／8.9 |

調整前のパート別の数値（抜粋、統合 LUFS／Mud 帯域 dB）は、レポートの第 2 節に全部ある。主な発見: ドラムがリードより 8〜16dB 大きい（キック +14dB）、クリーンギターが −23dB と小さい、14 番のブラスは描き出しで無音（音符が 3 つだけで鳴っていない）。

## 6. 限界（正直に）

- **耳で確認していない。** 「すっきり」の数字でも濁って聞こえることがある。ぐじゃぐじゃ指数は未校正。
- 目標値の【出】は主にパンク 5 曲・歌ありの録音の測定。歌のない曲のリード、鍵盤・弦・ブラスは【推】。Web の追加調査は今回できなかった（検索の上限）ため、docs/sound にある資料だけに基づく。
- 比較に使う大きさは RMS（左右の力の平均）で、K 特性の LUFS とは低域・高域の重みが違う。Demucs 由来の数字と比べると 2〜3dB のずれがありうる。
- パート別の数字は全体の仕上げの前で測る。全体の音との差は第 4 節（全体）で見る。MIDI の reverb の送りは含まれない。
- ドラムの volume を大きく下げると、ベロシティの効き方（音色）が変わる。1 回の反復は最大 6dB なので、大きな差は `--loop` の回数を増やすか、`drumMix.level` を使う。
- 自動調整は「パートの大きさ」を動かす。編曲の混み（ギター 2 本と鍵盤とリードが同じ音域）は、オクターブをずらす・休符を入れるなど人間の編曲で直す。
- 描き出しは 1 回約 3 分かかり、`--loop 3` で約 13 分。
