# 音の重ね方と曲の仕上げ方の技術（Claude Code がどの曲でも使えるように）

2026-10-29 人間「勉強した音の重ね方・音楽の作り方のテクニックを、すべてコードに共有できるようにして」。
クラウドの Claude がケルト100曲（銀の笛と百の夜）・ジャズ・歌の曲で学び、試し、点数と耳で確かめたことをまとめる。
好み（何が好き・嫌い）は docs/sound/composer-preferences.md、学んだ元の資料は下の「くわしい資料」。

## 1. 曲を作る前（設計）
1. その曲のイメージ（場面・物語・この曲だけの要素＝ただひとつ）を1行で書く。形・拍子・調・楽器・始まり方・終わり方は、それを伝えるために選ぶ
2. 「曲を決める表」を書き、ほかの曲と並べて、始まり方・終わり方・山の置き方・旋律の動き・リズムの形・主役の音色が似ていないか確かめる（似ていたら作る前に直す）
3. ジャンルの決まりごと（見本）を先に調べる。ケルト: celtic-study/README.md（装飾音・はずみ・ダンスの型・8小節の文法・旋法・15の編曲の型）

## 2. 音の重ね方（主役を立てたまま、厚く・細やかに）
山下達郎の重ね方の学び（layering-study.md）と、ケルト100曲での実験から:
- **主役は1つ**。主旋律の楽器を並べない（ケルトでは笛だけ。応える役も笛か、低い音域のチェロだけ）
- **主役を2重にする**: 同じ旋律を、少し遅らせて（1音ずつランダムに 0〜0.05拍）、反対寄り・小さめ・明るさを下げて重ねる → 深み（c100_common.finish の double）
- **和声の重ね（主旋律の下）**: 3度下（だめなら4〜5度下）の和音の音を、2本目・3本目に。左右に分けて小さく（c100_common.rich の choir）
- **内声の動き**: 弦の1本が、和音の中のテンション（9th・maj7・6th）から一音ずつ下りる（クリシェ）。止まって聞こえる所が動きだす（rich の inner）
- **床（ゆか）を敷く**: 主役が休む小節・止まる小節・前奏にも、うすい弦3声＋低音（チェロ）を必ず置く。音が落ちる所を作らない（floor_bed）
- **広がりのパッド**: 左右いっぱいに、ごく小さな長い和音（finish の pads）
- **それぞれ別の音域・別の左右に**: 低音（チェロ・コントラバス）／中低（竪琴の左手・ギター）／中（主役）／中高（和声・内声）／高（竪琴の倍音・グロッケン）。同じ音域・同じ左右に2つ重ねない
- **ピアノの音源（Salamander）は小さい**: 弦などと同じ大きさに聞かせるには、volume を 2〜2.5倍に。ピアノだけの場面は特に
- **楽器の数は場面ごとに決める**（区間の名前で決めない）。増やす順・減らす順そのものを物語にする（例: 灯りが1つ増えるごとに楽器が1つ増える）
- **速い曲の推進力**: 枠太鼓（ボーラン）の型＋ギターの開放和音のストローク（DADGAD 風: 3度を抜いた根音・5度・オクターブ・9度）。012（7.88点）の厚さ＝ボーラン＋ギター＋竪琴の3音オスティナート＋チェロ＋弦＋笛の和声（c100_common.drive）
- **重ねすぎに注意（2026-10-29 016 で確かめた）**: 速い曲（ホーンパイプ）に、ピチカート・内声・パッドを足したら 7.48→7.25 に下がった。速い曲は「ボーラン＋ギター＋竪琴＋チェロ＋弦＋笛の和声」までにして、細かい刻みの層を増やしすぎない。静かな曲は逆に、床・内声・パッドで点が上がりやすい
- **静かな曲には「高いきらめきの層」を入れる（2026-10-29 017 で確かめた: 7.05→7.27）**: グロッケンと竪琴の高い音（G5〜C7）を、和音の音でまばらに（グロッケンは2小節に1つ、竪琴は1小節に2〜3音、どれも弱く・残響多め）。合格した静かな曲（002・006・009・010・035）にはどれもこの層があり、7.0 前後で止まった曲にはなかった（c100_common.sparkle）。
  - 同じ 017 で効かなかったこと: 伴奏の厚さ（床・ピアノ2倍）7.05→7.05、内声の動きを外す 7.05→7.03、最後の音の仕上げ（高域＋3dB・音量＋2dB・低域と高域）±0.05、空間の効果音を外す 7.05→7.15
- **速い曲は「厚い弦（低めの3声）＋コントラバス」で上がる（023: 7.27→7.39→7.53）**。パッドと内声は入れない
- **作った効果音を外しても点はほぼ変わらない**（008 で比べた: 6.70→6.66）。空間は音楽の音で作ってよい
- **曲ごとの「ただひとつ」を音で作る例**: 5度だけの古い響き→山で初めて3度（041）／欠けた旋律が回るたびに埋まる（042）／同じ旋律が最後に半分の速さ（044）／和音の並べ方が狭い→4オクターブに開く（046）／遠くの笛が同じ音で返事（047）／音のない打音が先にリズムを刻む（050）

## 3. 空間（頭の中を支配する音）
- **空間は音楽の音で支配する**（2026-10-29 人間）。作った効果音（倍音の鳴り・息のような雑音）で埋めない。環境音は景色の気配にとどめる（音楽より −30dB 前後、音楽が大きい所では下げる＝ダッキング）
- 使ってよい空間の層: 楽器そのものの残響（--space dome / hall、wet 0.3〜0.4）、音楽を遅らせて暗くした遠い反射（far）、高域を1オクターブ上げて長い残響へ（shimmer・ひかえめ）
- 左右の広がり: --widen 1.32・--side-hpf 200（1.4 にすると左右の相関がマイナスになり、音がやせる）
- 環境音だけが鳴る時間を作らない（点数が下がる・人間もいやがる）
- 仕組み: assets-src/ai-songs/_gen/c100_air.py（MUSIC_FIRST）

## 4. 強弱と流れ
- 場面ごとに必要な強さを決める（0.6〜0.95 の曲線）。山は1曲に0〜2つ
- 曲の途中で急に小さくしない。特に前奏→最初の場面、笛が休む小節、終わりの場面
- 前奏は「楽器1つだけ」にしない（竪琴だけ・ピアノだけ・太鼓だけは −35〜−50dB になる）。その場面の空気（弦の和音とチェロ）を下に敷く
- 終わりは長く消えていかない（20秒以上沈むと「段差大」）。最後の場面は4〜6小節、最後まで弦が支え、消え方は最後のフェード（7秒）にまかせる
- 「遠い」「小さい」場面も、音量を下げずに、楽器の選び方（やわらかい打ち方・高い音域・残響）で表す

## 5. 書き出したあとの検査（1回目で合格しやすくする）
- 書き出す前: thickness_report（薄い小節の数・前奏の厚さ）→ 薄い小節 0 にしてから書き出す
- 書き出したあと: 音質の点数（Audiobox Aesthetics の PQ。tools/audio-check/aes-score-lowmem.py）と、2秒ごとの大きさ（前奏が小さい・急に小さい所・段差）
  - 目標: ふだんの曲 7.5 以上（目標8）。ケルト100曲は 静 7.2・動 7.8
  - 点数が低い原因の多く: 薄い（弦2声だけ・チェロなし・パッドなし）、前奏や休む小節が空く、終わりが長い、作った効果音・大きい環境音（CE＝楽しさが下がる）
- 点数だけで決めず、区間ごとに単調な所がないかを聞いて確かめる
- 4〜5分の曲は、長さが足りなければテンポを少し下げて合わせる（場面を空白でのばさない）

## 第3版で分かったこと（2026-10-29〜）
- **主役は笛**（旭さん「物語考えたら主役笛じゃない？」）。伴奏が旋律を持つ曲（003 のウェールズ型など）でも、笛を後から添える役にしない。伴奏の旋律は音量を下げて奥に置き、笛の入りを早くし、山と最後は笛が持つ。表に「笛が主役になっているか」を毎回書く。
- 伴奏が旋律を持つ曲は、笛との「同じ音・オクターブ・2度」のぶつかりを数えて直す: `python3 tools/celtic100/clash.py <曲.json> "<伴奏の旋律のパート名>"`。003 は 51 か所 → 意図した重なりだけに。オクターブ上をなぞるだけの所は「別の旋律」に聞こえないので直す。
- 共通の「アヴォイドノートの直し」（強い拍の、和音の半音上の音を半音下げる）は、和音の外の音にとどまること自体が仕掛けの曲（004 のドローンの曲）では止める: `S.fix_avoid = lambda t: 0`。止めないと E♭ が D に直され、緊張が消える。
- 同時に鳴らす音（和音）は、1つのパートに同じ時刻で2回 `at` しても1つしか鳴らない。和音は声部ごとにパートを分ける（003 の左手の和音）。
- 001: 楽器1つの前奏は小さくなりやすい（-44dB）。竪琴の前奏だけ barGain ×2.5、笛が休む小節にも竪琴を1つ鳴らして音を落とさない → 7.38 から 7.49。
- 1つの音の長さは64拍まで（それより長いと「拍が読めません」で書き出しが止まる）。ドローンのように曲じゅう続く音は、約60拍ごとに2つのパートで4拍重ねてつなぐ（004）。
- 002: 音量の谷を直しても点数が 7.30 → 7.28 と変わらなかった。点数を止めていたのは谷ではなく、左に寄ったギターだけの薄さ。3階から右に別の音域のギターを足し、左右に広げた（上るほど吹きぬけが広がる、という曲の中の理由で）。
- 前奏が「長い音1〜2つだけ」「楽器1つだけ」だと、ほぼ必ず -40dB 以下に沈む（001 竪琴 -44、004 ドローン -45、006 ピチカート -34、007 低い弦 -47）。前奏の形は曲ごとに変えてよいが、その楽器の音量は前奏だけ ×2.5〜3.5 にし、長い音だけで何小節も引っぱらない（途中から動きはじめる）。書き出す前に表の「始まり」の楽器を見て、1つだけなら最初から前奏の倍率を決めておく。
- 004: バグパイプのドローン（本物の録音 G2・G3）は、volume 0.075 では -45dB と、とても小さい。伴奏の主役にするなら barGain ×3 前後。
- 枠太鼓（frameDrum）は、0.25〜0.33 拍の短い音が鳴らなかった（010 の前奏の連打が無音 -80dB）。連打や3つ割りは2つのパートに交互に置き、1打を 0.5 拍以上にする。
- 1/3 拍の位置を丸めると「R:0」ができ、書き出しが止まる。作った JSON から長さ0の休みを取りのぞく（010）。
- ギターの開いた和音は、D の和音で D2（音域の外）が出る。open_chord の最低音を E2（52 から）に（010）。
- **枠太鼓（frameDrum）の鍵（2026-10-30 に試しの書き出しで測った）**: C3（大きい太鼓）と E3（小さい太鼓）はよく鳴る。D3（手のひら）はとても小さく（約 -39dB）、A3・C#3・F#3 はほとんど鳴らない。ボーランの低い打ち＝C3、高い打ち＝E3。c100_v2.bodhran() もこれに直した（それまでの D3・A3 では、ボーランがほとんど聞こえていなかった）。
- 書き出しの列（q.sh）は、コンテナが再起動すると止まって消える。再起動のあとは列を確かめて、並べ直す。
- **バグパイプ（instrument bagpipe）の録音は約4秒で消える（ループしない）。とても小さいので gainDb=18（barGain 約2.2 で笛より約6dB下）**。G2 は G3 より約20dB小さい。ドローンは2拍ごとに2つのパートで交互に鳴らし直し、少し重ねて途切れないようにする（004。1・2回目はドローンがほとんど鳴っておらず 6.70・6.93）。長い音を使う録音の楽器は、使う前に「長い音1つ」を試しに書き出して、どこまで鳴るかを測る（F-process.md の 3）。
- チェロの D2 あたりの長い音は、D3 より約20dB小さく鳴る（007 の前奏が -64dB。試しの書き出しで測った）。低い弦だけで始める前奏は、1オクターブ上（D3 あたり）を使う。
- **枠太鼓（frameDrum）とインチ違いのタム（inchTom）の録音は、とても小さい**（笛と並べて試しの書き出しで測ると、volume 0.2〜0.3 で笛より約37dB 小さい）。ボーランを聞かせたい曲は gainDb=18（上限）と volume 0.35 にする（010。それまでの 012 なども、ボーランはほとんど聞こえていなかったはず）。
- 弦（チェロ・ビオラ）の長い音（2小節近い全音符）は、立ち上がりが遅く、短い音より約20dB小さく測れた（007）。前奏を弦だけで始めるときは、長い音で引っぱらず、2〜3拍の動く音で始める。
- 作曲ソフトの速さは 40〜260 まで。速い 6/8・9/8 は「1拍＝付点4分」で書き（9/8 は1小節3拍）、8分音符を 1/3 拍にする（010 のジグ、011 のスリップ・ジグ）。長さ0の休み（R:0）は取りのぞく。
- **【大事】barGain で強さ（velocity × barGain）が 2 を超えると、作曲ソフトがその音をほぼ無音にしていた**（velocityScale が 2 より大きい数を「MIDI の数字 0〜127」とみなして 1/100 にするため）。2026-10-30 に src/audio/ai-song.ts で「2 で止める」ように直した。
  - これまで「前奏だけ ×2.5〜5」「ドローン ×3.2」などで音を大きくしたつもりが、逆にほぼ無音になっていた（001 の前奏 -44、004 のドローン、007 の前奏 -64、010 の前奏 -61 の本当の原因）。
  - 直したあとは、barGain 0.7 のバグパイプのドローンが笛より約10dB大きく鳴る。大きさは必ず tools/celtic100/probe.py で笛と並べて測ってから決める。
  - 音を大きくしたいときは、barGain は 1.5 くらいまでにし、それ以上は gainDb（上限 +18）を使う。
- 録音の弦（VSCO）は強さで音色の層が変わり、大きさがとても非線形（チェロ: 強さ 0.9 → 笛より約15dB小さい、2.0 → 笛より大きい）。弦だけの前奏は、強さ（velocity×barGain）が 1.3〜1.8 くらいになるように決め、probe.py で確かめる（007）。

## 2026-11-01 ケルト100曲 012〜017 で分かったこと
- barGain は音の強さ（velocity）に掛かり、強さは 2 で頭打ち。×2 より大きくしても大きくならない。前奏だけ大きくしたいときは、前奏用に volume の大きい別パートを作る（015 のオルガン）。
- 長い音のバイオリン（重音のドローン）は、笛より約 8dB 小さく鳴る。短い音の応答は逆に笛より約 10dB 大きく鳴った（012）。同じ楽器でも、長い音と短い音で大きさが大きく違う。
- ピチカート（patch pizzicato）は笛より約 10dB 小さい → gainDb 6 前後（014）。
- リードオルガン（reedOrgan・instrument pad）は思ったより小さい。和音（3音・強さ 0.6・volume 0.1）でも笛より約 14dB 小さかった → 本編 gainDb 6、オルガンだけの前奏は gainDb 12（015）。1音だけの試し書き出しは、前の笛の残響が混ざって読み違えた。試し書き出しは「実際の和音・実際の強さ」で並べること。
- クラリネット1音は笛とほぼ同じ、ファゴット（D2）は約 3dB 小さい（017）。
- ピアノは1音で、×1.4 のとき笛とほぼ同じ。右手の和音（3音）は volume 0.08 前後（016）。
- 句を「4小節ごと」に置くとき、句そのものが2小節しかないと、残りの2小節は笛が消えて -50dB に沈む。置く間隔と句の長さを必ず合わせる（014 の森）。
- 入れ物が入れ替わると huggingface への接続が 403 で止まることがある。点数の重みは HF_HOME=/tmp/hf に残っていれば HF_HUB_OFFLINE=1 で読める。
- 004: バグパイプのドローン（録音は約4秒で消える・G2 が小さい）では 6.7〜6.99 から動かなかった。遠いチェロ（G3）とビオラ（D4）の長い音のドローン（2小節ごとに2パートで交互に弓を返す）に替えると 7.11。チェロ volume 0.02・gainDb 2、ビオラ 0.017 で笛の約5dB 下（チェロは 0.1・gainDb 6 だと笛より約6dB 大きかった）。
- 2026-11-01: クラウドの入れ物は、返事を終えて待っているあいだに止められる（再起動で書き出しの列が消える）。書き出しは、返事を終えずに終わるまで待つ。
- 弦合奏（stringEnsemble）の長いふくらみは、volume・barGain を上げても前奏の大きさがほとんど変わらなかった（031）。前奏を大きくしたいときは、ビオラ・チェロなど単独の弦か、笛で始めるほうがよい。
- ピアノの前奏は強さ（barGain）が音量に比例しない：×1 で本編より約12dB 小さく、×2 で約6dB 大きかった（030）。×1.45 で合った。
- 2026-11-01（046・047）: 始まりが弦の持続だけの曲は、本編より 10〜20dB 小さく聞こえやすい。barGain を2倍にしても約4dB しか上がらない（046: −42 → −31dB）。047 では始まり用のコントラバス（0.07・gainDb 8）とチェロ（0.03・gainDb 8）を別のパートにした。
- 2026-11-01（047）: 低い弦だけの始まりは、始まり用のコントラバス（0.07・gainDb 8）＋チェロ（0.03・gainDb 8）で −46 → −30dB（本編の中央値 −26dB）。点数は 7.35 → 7.37。
